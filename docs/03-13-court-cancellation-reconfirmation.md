# 코트 매칭 취소 금액 재확인 · R08

2026-10-01 · 구현·검증 완료

취소 확인 화면을 연 뒤 한국 날짜나 입금·환불 기록이 바뀌면, 사용자가 본 금액과 실제
취소 결과가 달라질 수 있다. 이미 승인한 날짜별 환불율은 유지하고 확인 절차를 보완한다.
화면의 시계만으로 버튼을 막는 대안은 다른 탭·운영자 대조·서버 잠금 대기를 처리하지 못한다.
새 결제 기능·스케줄러·DB 열·의존성은 추가하지 않는다.

- 본인만 `GET /api/v1/court-match-applications/{id}/cancel`로 최신 취소 안내를 조회한다.
  서버는 신청/경기 식별자, 신청 상태, 정책 버전, 시작 시각, 참가비, 실제 수령/지급/처리 중
  금액, 적용 환불율과 미지급 반환액, 유효 기한을 묶은 확인값을 발급한다.
- `POST`는 `{ cancellationFingerprint }`를 필수로 받는다. 계정·Match 잠금을 얻은 뒤
  서버 현재 시각으로 상태를 보정하고 최신 확인값을 비교한다. 과거 시각이나 브라우저의
  금액을 환불 계산에 사용하지 않는다. 확인값은 변경 감지용이며 인증/서명이 아니다.
- 변경 시 `409 CANCELLATION_PREVIEW_CHANGED`를 반환하고 개인 취소, 자리 반환, 채팅 탈퇴,
  취소 알림을 실행하지 않는다. 시간 경과에 따른 기존 자동 만료·전체 취소 보정은 유지한다.
- 화면은 처음 열 때 최신 안내를 읽고 확인 중인 금액을 고정한다. 충돌 시 최신 안내를 다시
  읽어 변경 사실을 알리고 다시 누르게 한다. 조회 실패 시 오래된 금액으로 확정할 수 없다.
- 성공 응답을 놓쳐 재시도해도 본인의 이미 완료된 자발적 취소는 재실행하지 않는다.
  저장된 정책 환불액은 유지하고 현재 미지급 반환액을 돌려준다. 알림·채팅 처리는 중복하지 않는다.
- 탈퇴 시 취소는 기존 탈퇴 미리보기의 확인값 검증 안에서 처리한다. 해당 경로를 우회하지 않는다.

검증 대상: 한국 자정의 100→50%, 50→0%, 미확정→확정, 입금 대조 변경, 시작 시각 도달,
타인 요청·본문 누락·위조 확인값, 중복 요청, 최신 안내 재조회 실패, 모바일 재확인 흐름.

## 검증 결과

- Node.js 22.23.2에서 린트·타입 검사·단위/실제 DB 테스트 410개·프로덕션 빌드 통과.
  전용 로컬 `rally_r05_e2e`를 사용하고 운영 DB 환경 변수 두 개를 모두 덮어썼다.
- 실제 PostgreSQL 행 잠금 대기를 확인한 뒤 한국 자정을 넘겨, 오래된 금액으로 취소되지
  않음을 검증했다. 자정 100→50%, 50→0%, 입금·확정 변경, 중복 요청, 경기 시작,
  입금 확인 기한 만료와 자동 만료 기록 보존도 확인했다.
- 모바일 E2E 6개 통과: 재확인, 최신 금액 재조회 실패 후 복구, 기존 참가 취소·환불,
  구성 부족 후 운영자 취소, 탈퇴·거래 인계 경로. 390px 화면에서 가로 넘침·실행 오류가
  없고, 최신 금액과 재확인 버튼이 보이는 스크린샷을 확인했다.
- GET/POST 비로그인 401, 타인 미리보기 404, 필수 확인값 누락 422, 빈 본문 400 확인.
- 새 마이그레이션은 없다. 크론 보류를 유지한다. 이전 클로드 커밋 `6892788`과
  CI 수정 `873b3f4`를 보존했다. 반영 전 원격 main과 일치하며 추가 변경이 없음을 확인했다.

## 운영 반영 시 주의사항

DB 마이그레이션 없이 화면과 API를 함께 배포한다. 원격 CI와 Vercel 운영 배포가 성공한
것을 각각 확인하고, 운영 상태 확인 API로 서비스 응답과 DB 연결을 점검한다.
본문 없는 구 클라이언트는 새 POST에서 취소가 거절되므로 화면을 새로고침해야 한다.
