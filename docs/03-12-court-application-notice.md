# 코트 매칭 신청 전 안내와 확인 기록

2026-09-13 · R06 첫 구현 단위 · 구현·검증 완료 · 사용자 승인으로 운영 반영 진행

## 문제와 범위

신청 시 일시·참가비만 확인하고 나중에 환불 규칙을 처음 보는 문제를 줄인다. 이미 승인한 코트 매칭 정책을 신청 전에 간결하게 보여 주고, 서버가 제시한 조건과 이용자의 확인 시각을 신청에 보존한다. 긴 자유 입력이나 새로운 결제 기능은 추가하지 않는다. 확인 체크만 저장하는 대안은 당시 조건을 확인할 수 없어 채택하지 않는다.

등록된 코트·일시·경기 유형·최소 구성·참가비·승인 방식·이체/확인 기한 규칙·취소 사유별 반환·이용 안내를 기록한다. 정확한 승인 후 입금 기한은 기존 paymentDueAt/confirmationDueAt으로 계속 기록하고 이체 전에 표시한다. 신청 안내의 기한 규칙과 승인 후 실제 기한을 혼동하지 않는다.

참가비에 포함되는 레슨·공·장비 등 새로운 제공 약속은 사용자의 포함 범위 답변 후 확정한다. 이번 첫 단위는 현재 등록 정보와 이미 확정된 정책만 다룬다. 사업자 신원·현장 연락·영수증 발급·보관 기간이 모두 확정됐다는 의미가 아니다.

## 서버·화면 계약

- 서버가 안내 버전과 내용 해시를 생성한다. 해시는 표시한 조건의 변경 감지용이며 서명·열람 증명이 아니다.
- 이용자는 신청 모달에서 현재 조건을 확인하고 확인 체크 후 신청한다. API는 확인 여부와 해시를 필수로 받고 Match 행 잠금 안에서 최신 조건으로 검증한다.
- 비용·일시·게임 유형·최소 구성·환불 규칙·운영 안내가 달라지면 신청하지 않고 409로 최신 안내를 다시 확인하게 한다. 브라우저의 금액·환불 문구를 저장하지 않는다.
- 확인된 안내 스냅샷·버전·확인 시각은 신청 생성과 같은 트랜잭션으로 기록한다. 기존 신청에는 과거 동의를 만들어 넣지 않는다.
- 본인 신청과 해당 운영자·인계 담당자의 거래 조회에서 당시 안내를 볼 수 있다. 다른 참가자의 기록을 공개하지 않는다.
- 일반 매칭, 프로필 스냅샷, 이전 자발적 취소와 반환 계산, 크론에는 영향을 주지 않는다.
- 화면은 진행 조건·사유별 반환 요약을 먼저 보여 주고 전체 안내를 펼쳐 볼 수 있게 한다. 원문과 요약을 모두 저장해 이후 문구 변경과 구분한다.
- 이용약관의 코트 환불 설명도 확정 전 종료·확정 후 본인 취소·경기 전체 취소로 구분했다. 개인정보 안내에는 당시 조건과 확인 기록의 처리 목적·열람 범위를 명시했다. 이 갱신은 이미 확정된 로직의 설명이며 새 환불율·노쇼 제재·면책 범위를 정하지 않는다.

## 남은 운영·법률 확인

실제 공급 범위 답변과 별개로, 공개 전 사업자 표시 정보와 담당자의 운영 체계를 확보해야 한다. 통신판매중개 해당 여부는 실제 계약·제공 업무를 확인해야 하며, 직접 계좌이체만으로 중개 의무가 없다고 단정하지 않는다. 전자상거래법 제20조의 사전 고지·사업자 정보 제공·분쟁 대응 내용은 [국가법령정보센터](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0020&lsiSeq=282793&urlMode=lsScJoRltInfoR)에서 2026-09-12 확인했다. 면책 문구는 [약관법 제7조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0007&lsiSeq=260021&urlMode=lsScJoRltInfoR)의 제한과 실제 운영 역할을 함께 검토해야 한다. 기존 100/50/0 규칙의 법적 적합성을 이번 코드 검증으로 확정하지 않는다.

## 검증과 다음 반영 시 주의사항

- 클로드의 `2cf750b`, `b3c7c31`과 미커밋 `tests/e2e/first-run.tour.ts` 변경을 보존했다.
- 린트·타입 검사·Prisma 스키마 검증·단위 테스트 314개·프로덕션 빌드 통과. PostgreSQL 전용 로컬 DB `rally_r05_e2e`에 31개 마이그레이션 적용 후 실제 DB 테스트 69개 통과.
- 조건 누락·거짓 체크·위조/오래된 해시 거절, 등록 조건 변경 후 재확인, 중복 신청 차단, 승인 방식별 프로필 공개, 과거 신청의 NULL 보존, 본인/운영자 기록 조회와 다른 이용자 비공개를 검증했다.
- 모바일 E2E는 신청 전 확인 2개와 기존 신청·입금·채팅·개인 취소·제공 불가 취소·탈퇴 후 거래 인계 등 8개를 확인했다. 첫 통합 실행은 9개 통과, 접힌 안내의 금액을 잘못 찾던 환불 테스트 1개를 실제 남은 반환액으로 수정하고 해당 흐름을 재실행해 통과했다. 390px 화면의 가로 넘침·실행 오류가 없으며 신청 요약과 당시 기록 스크린샷을 직접 확인했다.
- R05의 `50acb6c`는 main·운영 DB·Vercel 반영을 완료했다. 이 R06 첫 단위는 2026-09-13 사용자가 후속 커밋·푸시·배포·main 반영을 승인했다. R05 복원 리허설 DB와 임시 운영 환경 파일은 정리했고 보호된 원본 백업은 유지했다.
- 배포 전 fetch로 main의 클로드 커밋 `2cf750b`, `b3c7c31`이 origin/main보다 앞선 것을 확인했다. 새 사용자 승인에 따라 기존 커밋은 변경 없이 함께 푸시하며 미커밋 `tests/e2e/first-run.tour.ts`는 제외한다.

운영 반영에는 `20260912110000_court_application_notice`의 nullable 열 3개를 사용한다. 기존 신청은 NULL 그대로 보존하고 과거 확인 기록을 만들지 않는다. 현재 `.env.local`은 운영 DB를 가리키므로 미적용 스키마를 사용하는 이 코드를 그 연결로 실행하지 않는다. 테스트·개발 확인에는 `DATABASE_URL`과 `DATABASE_URL_UNPOOLED`를 모두 별도 로컬 DB로 덮어쓴다. 배포 전 최신 main 및 클로드 작업과 다시 비교하고 이번 파일만 반영한다.

공급 범위 답변, 실제 계약 주체·연락 창구·현장 진행 책임과 법률 검토, 보관·파기 기준은 다음 결정 사항이다. `03-8`에 적힌 전체 R06이 완료된 것은 아니다. 기존 CI의 Node 22 오전/오후 표기 실패 2건은 별도로 남아 있으며 이번 작업에서 수정하지 않았다.
