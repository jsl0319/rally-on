# 코트 매칭 운영자 전화 문의

2026-10-03 · 구현·로컬 검증 완료, 운영 미반영 · [03-14](03-14-court-service-scope-and-support.md) §10 후속

## 목적과 범위

회원은 상세의 경기 조건으로 신청 여부를 판단한다. 신청 전 담당자 문의 연결은 추가하지 않는다. 신청 접수 후 입금·시설·현장 문의는 실제 코트 운영자의 업무용 번호로 할 수 있게 한다. 첫 제공은 기존 코트 설정과 참가 상세에 연락처·전화 걸기를 더하는 범위다. 새 개인 DM·전화 중계·번호 검색 서비스·의존성은 추가하지 않는다. 참가 확정 후 기존 Match 단체 채팅은 유지한다.

## 확정 기준

- 신청 접수 후 `PENDING`, `ACCEPTED`, `CONFIRMED` 본인에게 경기 종료 24시간까지 공개한다. 다른 회원의 신청이나 공개 목록 응답으로는 조회할 수 없다.
- 철회·거절·만료·취소되었거나 경기 전체가 취소된 신청은 미처리 입금·환불이 있을 때만 계속 공개한다. 종료 24시간이 지나도 미처리 거래는 해결까지 유지한다.
- 참가자가 탈퇴·정지된 경우에도 기존 인증으로 접근하는 `내 거래 정리`에서 본인의 미처리 거래에 같은 연락처 공개 기준을 적용한다. 일반 서비스·채팅 권한을 재개하지 않는다.
- 미처리 거래는 실제 반환 잔액, 처리 중·확인 필요 환불, 또는 입금 알림 후 아직 대조하지 않은 건이다. 대조 결과가 0원으로 확인된 경우 입금 알림만을 근거로 무기한 공개하지 않는다. 이후 분쟁은 기존 Rally On 문의로 처리한다.
- 운영자 탈퇴·공개 중단 및 시설·운영자 자격 비활성화 시 전화번호를 숨기고 기존 문의 경로를 남긴다. 해당 경로는 운영자의 입금 확인·환불 이체 의무를 대신 완료 처리하지 않는다.
- 네이버·지도 검색 결과나 비공개 심사 정보에서 번호를 복사하지 않는다. 운영자가 실제 문의 가능한 국내 업무용 번호·연락 가능 시간을 입력하고 해당 신청자 공개를 확인한다. 번호 소유·실제 연결 여부를 검증했다고 표시하지 않는다.
- 연락처 변경 시 현재 번호를 사용한다. 과거 번호를 신청 안내나 참가자 이력에 복사하지 않는다. 공개 중단은 번호·연락 시간·현재 공개 확인 시각을 지우며, 다시 등록할 때 공개 범위를 다시 확인한다.
- 연락 가능 시간은 운영자 입력 안내이며 응답 보장·자동 전화 연결·시간 외 차단을 약속하지 않는다. 전화 앱 실행은 회원이 버튼을 누를 때만 한다.

새 코트 매칭을 최초 공개할 때 전화번호·연락 가능 시간·공개 확인을 필수로 받는다. 초안 저장에는 요구하지 않고 기존 공개 경기에는 연락처 등록 안내를 제공한다. 최초 공개와 공개 중단이 동시에 일어날 때 Court 행 잠금으로 순서를 보장한다. 기존 공개 경기에는 임의의 번호를 채우거나 신청을 중지하지 않는다.

## 데이터·API

Court에 현재 업무용 전화번호, 연락 가능 시간, 공개 확인 시각, 연락처 수정 버전을 추가한다. 전부 새 데이터만 기록하고 기존 값은 NULL/0으로 시작한다. 계좌·참가비·진행 조건과 독립된 연락 정보이며 공개 경기의 시간·금액 불변 정책을 바꾸지 않는다.

- 본인 `GET /api/v1/operator/courts`에서 `operatorContact`와 `contactVersion`을 반환한다.
- `PUT /api/v1/operator/courts/{courtId}/contact`: `phone`, `hours`, `publicationAgreed: true`, `expectedVersion`. 국내 번호 형식을 검증해 숫자로 정규화하며 연락 가능 시간은 1~80자다.
- 같은 경로 `DELETE`: `expectedVersion`만 받고 공개를 중단한다. 버전 불일치는 409, 소유하지 않은 Court는 404다. 활동 중인 소유자의 권한을 서버에서 검증한다.
- 본인 제한 거래 `GET /api/v1/me/transactions`의 각 항목에도 같은 기준의 `operatorContact`를 반환한다. 이 응답에도 `Cache-Control: no-store`를 적용한다.
- 참가 상세의 `participation.operatorContact`는 조건이 맞는 본인 신청에서만 반환하며 나머지는 null이다. 번호·시간·`tel:` 링크를 포함한다. 응답은 저장하지 않는다(`Cache-Control: no-store`).
- 일반 공개 Slot·매칭 목록·신청 안내 스냅샷·로그에는 번호를 추가하지 않는다. 기존 참가 확정 전 채팅 제한도 유지한다.

## 화면

운영 홈에 연락처 관리 진입점을 둔다. 등록·수정 화면에는 전화번호, 연락 가능 시간, 공개 범위 확인을 표시한다. 기존 번호를 변경하거나 공개 중단할 수 있으며 상태 충돌은 다시 불러오도록 안내한다.

상세의 위치와 현장 안내에서 신청 전 `이용·입금 문의` 링크를 제거한다. 신청 후에는 별도 운영자 문의 영역에 전화번호·연락 가능 시간·전화 걸기를 표시한다. 전화 이용이 불가능하거나 거래 문제·앱 문제가 있는 경우 기존 Rally On 문의로 갈 수 있다. 단체 채팅에 개인 입금·계좌 내역을 올리도록 유도하지 않는다.

## 검증 결과

- `npm run check` 통과: 린트, 타입 검사, 57개 파일의 433개 테스트(단위 353개·실제 DB 80개), 프로덕션 빌드.
- Prisma 스키마 검증·Client 생성 및 전용 로컬 DB 마이그레이션 적용을 확인했다. 운영 DB에는 연결하거나 변경하지 않았다.
- 전화번호·동의·시간 누락과 잘못된 형식, 비로그인·타인 수정, 오래된 수정 버전, 신청 전·다른 회원의 연락처 비노출, 승인 대기·입금 대기·확정·종료 24시간 경계를 확인했다. 취소 후 반환 잔액, 0원 대조 완료, 운영자 탈퇴·공개 중단도 검증했다.
- 모바일 E2E 9개 통과: `court-contact`, `court-application-notice`, `court-composition`, `court-cancellation`. 연락처 등록 → 새 공개 필수 검증 → 신청 → 전화 링크 → 번호 변경 → 공개 중단과, 탈퇴 후 본인 미처리 환불의 제한 거래 화면을 확인했다. 실제 전화는 걸지 않았고 링크와 노출 권한을 검증했다.
- 변경한 모바일 화면을 직접 확인했으며 가로 넘침·브라우저 실행 오류가 없었다. 재개 후 별도 로컬 브라우저에서도 페이지 표시와 오류 오버레이 부재를 확인하고 종료했다.
- 기존 구성 취소 E2E의 날짜 경계 가정을 수정했다. 자발적 취소 직후 환불액을 기록해 운영자 전체 취소 후에도 그대로 유지됨을 검사하며, 날짜별 환불 정책 자체는 바꾸지 않았다.

## 운영 반영과 남은 범위

커밋·푸시·운영 DB 적용·배포는 아직 실행하지 않았다. 운영 반영 때에는 함께 준비한 `20261001010000_court_service_scope`와 `20261002010000_court_operator_contact` 마이그레이션을 적용한 뒤 대응 코드를 배포한다. 기존 경기 연락처를 임의로 채우지 않는다. 기존 운영자에게는 연락처 등록 안내가 표시되고 새 경기 공개부터 필수 조건이 적용된다.

전화번호는 운영자가 등록·공개 확인한 정보이며 실제 소유·연결 여부의 인증은 제공하지 않는다. Rally On의 외부 문의 채널·응대 시간, 공개 제공자 정보와 약관 검토는 별도 미확정 항목으로 유지한다. 크론 보류도 유지한다.
