# Rally On 코트 파트너 화면 명세

## 1. 문서 정보

| 항목 | 내용 |
| --- | --- |
| 문서명 | Rally On Court Partner Screen Specification |
| 문서 상태 | Draft v0.3 |
| 제품 단계 | Court Partner Pilot 설계 |
| 기준 문서 | `01-product-overview.md`, `02-prd.md` |
| Core 화면 명세 | `03-screen-spec.md` |
| 구현 범위 | Core MVP 다음의 필수 Pilot. 결제·환불·정산은 별도 단계 |

이 문서는 코트 운영자가 준비한 코트 시간을 공급하고, 일반 모집자가 그 시간에 제휴 코트 세션을 열어 참가자를 모집하는 흐름을 정의한다. 일반 사용자는 제휴 코트에 예약 요청을 보내지 않는다. 참가 신청은 기존 Match 흐름과 동일하게 세션 모집자에게 보내며, 운영자는 이를 승인하거나 거절하지 않는다.

`03-screen-spec.md`의 Core MVP 화면과 구현 범위를 분리하기 위한 문서다. Court Partner Pilot은 Core MVP 다음에 반드시 구현하지만, 앱 결제·환불·정산과 일반 사용자 코트 예약은 별도 승인 전까지 포함하지 않는다. Commerce가 승인되면 이 문서의 Pilot 화면을 덮어쓰지 않고 `07-court-commerce-design.md`의 별도 상태·화면 원칙을 추가한다.

### 1.1 시각 기준

- Figma 파일의 `Court Partner Pilot` 페이지를 기준 화면으로 사용한다.
- OP01 운영자 등록, OP02 심사 상태와 CP01 제휴 코트 세션 탐색이 작성되어 있다.
- CP01은 390 × 844 기준이며 대표 코트 사진 또는 기본 일러스트, 공개 상태 칩(예: `모집 중`), `참가 신청은 코트 매칭을 연 모집자에게 보내요`를 표시한다.
- 모바일 아트보드는 `390 × 844`, 기존 Rally On 색상·간격·모서리 토큰과 Noto Sans KR을 사용한다.
- 웹 구현 전에는 Figma에 해당 화면·상태를 먼저 추가하고, 카드와 하단 CTA의 간격을 같은 기준으로 검토한다.
- 2026-08-28에는 사용자가 Figma 사용량 한도로 Court Partner Pilot의 **소스 선구현**을 승인했다. 이 예외에서는 기존 `Court Partner Pilot` 페이지를 읽기 기준으로만 사용하며, OP01·OP02·IR01을 포함한 Figma 쓰기·동기화는 한도가 해제된 뒤의 별도 요청에서만 한다.

### 1.2 첫 진입과 공통 인증

비로그인 첫 화면 S01에서 `테니스장을 운영하고 있어요`를 선택하면 메이트 이용자와 동일한 카카오 계정으로 인증한 뒤 OP01로 이동한다. 운영자 등록에는 일반 테니스 프로필 온보딩을 요구하지 않으며, 이 선택만으로 별도 운영자 계정이나 영구 역할을 만들지 않는다. 인증된 사용자의 운영 권한과 공개 가능 여부는 OP01 신청 상태로만 판단한다.

일반 회원이 제휴 코트 세션을 열거나 참가하려면 기존 Match 정책대로 테니스 프로필 온보딩을 완료해야 한다.

## 2. 제품 단계와 제외 범위

### 2.1 Court Partner Pilot

소수의 운영자와 함께 초보자가 코트를 따로 예약하지 않아도 참가할 수 있는 제휴 코트 세션을 제공하는 필수 확장 단계다.

- 운영자 등록, 심사와 공개 권한 확인
- 코트·개별 코트 면과 비공개 시간대 초안 등록
- 공개 가능한 CourtSlot 관리
- 일반 모집자의 제휴 코트 세션 개설
- 일반 사용자의 제휴 코트 세션 탐색과 참가 신청
- 기존 모집자의 참가 수락·거절·마감·완료 흐름 재사용

Pilot은 운영자가 시간 공급을 승인한 뒤 다시 예약 요청을 처리하는 구조가 아니다. `AVAILABLE` Slot을 하나의 Partner Court Match에 원자적으로 연결하는 것은 서버 내부의 공급 배정이며, 이용자 UI에서 코트 예약이나 운영자 승인으로 표현하지 않는다.

### 2.2 별도 단계

다음은 Pilot에 추가하지 않는다.

- 일반 사용자의 코트 예약 요청, 예약 목록, 예약 승인·거절
- 앱 내 결제, 환불, 수수료, 운영자 정산
- 운영자의 참가자 선택·실력 심사
- 참가자별 좌석 판매 또는 분할 결제
- 범용 실시간 채팅, 개인 DM, 일반 파일·음성 메시지, 접속·입력 중 표시, 코치·레슨 상품, 정기권·쿠폰·포인트. 단, 모든 Match에 공통으로 발신자의 최신 일반 메시지가 다른 모든 방 멤버에게 확인됐을 때만 보이는 제한된 `읽음` 표시와, 방 멤버 전용 JPEG·PNG·WebP 사진(메시지당 최대 3장·각 5 MiB)은 재사용한다.
- 외부 예약 시스템 자동 동기화

향후 Commerce를 검토하더라도 결제 대상·계약 주체·환불 책임이 확정되기 전에는 화면과 API를 만들지 않는다. Commerce 검토가 일반 사용자 CourtBooking 모델을 다시 도입하는 근거가 되지 않는다.

## 3. 역할과 책임

| 역할 | 하는 일 | 하지 않는 일 |
| --- | --- | --- |
| 코트 운영자 | 코트·시간대 공급, 공개·중지, 운영상 안내 | 참가 신청 수락·거절, 이용자 실력 심사 |
| 세션 모집자 | 공개 Slot을 Match에 연결, 모집 조건 입력, 참가 신청 수락·거절 | 운영자 대신 시간 재고 수정, 다른 운영자 시간 사용 |
| 매칭 참가자 | 제휴 코트 세션의 조건을 확인하고 같이 치기 신청 | 운영자에게 코트 예약 요청, Slot 상태 변경 |
| 플랫폼 관리자 | 운영자 심사, 예외·분쟁 처리 | 일반 참가 신청을 대신 수락 |

`세션 모집자`와 `매칭 참가자`는 모두 일반 회원이다. 한 회원이 어떤 세션에서는 모집자이고 다른 세션에서는 참가자일 수 있다. 운영자 시간 공급 권한과 모집자의 참가 승인 권한은 데이터 모델·API·화면 상태로 절대 합치지 않는다.

## 4. 핵심 UX 원칙

### 4.1 사용자 언어는 “코트 매칭”으로 통일한다

일반 사용자 화면에서 `예약 가능`, `예약 요청`, `승인 대기`, `코트 예약 확정`을 사용하지 않는다.

- 하단 메뉴: `코트 매칭`
- 목록 제목: `다가오는 코트 매칭` — 기간을 주 단위로 제한하지 않으므로 `이번 주`로 쓰지 않는다.
- 상세 CTA: `참가 신청하기`
- 보조 문구: `참가 신청은 코트 매칭을 연 모집자에게 보내요.`

일반 사용자 화면의 상태 칩은 짧은 상태만 보여 준다: Slot은 `열기 가능`·`모집 중`·`이용 완료`·`연결 중지`·`취소됨`, 연결된 Match는 `모집 중`·`모집 마감`·`이용 완료`·`종료됨`·`취소됨`이다. 상태를 설명하는 문장은 카드·상세의 제목이 맡는다. 서버는 이 공개용 문구를 운영자 화면 문구와 별도의 맵으로 관리한다.

운영자 화면에서만 공급 관리 맥락으로 `모집 가능한 시간`, `공개 시간`, `사용 중인 시간`, `세션 사용 중`을 사용한다. 일반 사용자에게도 공개 상태는 보여 줄 수 있지만, 상태별 행동은 세션 개설 또는 세션 참여로만 제한한다.

### 4.2 시간 공급과 참가 승인을 분리한다

운영자는 공개 Slot을 관리한다. 온보딩을 마친 일반 모집자가 `AVAILABLE` Slot을 선택해 Match를 만들면 서버는 Slot을 `ALLOCATED`로 바꾸고 Match에 연결한다. 이후 참가자의 `PENDING`, `ACCEPTED`, `REJECTED`는 기존 `MatchApplication` 상태를 사용하며 세션 모집자만 변경할 수 있다.

운영자에게는 참가자 프로필, 참가 신청 메시지, 수락·거절 CTA를 제공하지 않는다. 참가자에게는 운영자 승인 대기 상태를 제공하지 않는다.

### 4.3 공개 여부와 공급 상태를 분리한다

새 Slot은 `DRAFT`·`PRIVATE`로 시작하고, 한 번 공개하면 상태가 바뀌어도 계속 공개할 수 있다. `PUBLIC`은 이용자가 시간의 현재 상태를 확인할 수 있다는 뜻이고, `AVAILABLE`, `ALLOCATED`, `ENDED`, `BLOCKED`, `CANCELLED`은 그 시간에 할 수 있는 행동을 정하는 공급 상태다. 한 번도 공개하지 않은 초안을 취소한 경우에는 비공개를 유지할 수 있다.

공개 후에는 코트 면·일시·비용·현장 정원·이용 안내를 직접 수정하지 않는다. `AVAILABLE` 시간의 실수는 `BLOCKED`로 공개 중지한 뒤 새 `DRAFT`를 만드는 방식으로 정정한다. `BLOCKED`와 `CANCELLED`는 Pilot에서 다시 `AVAILABLE`로 열지 않는다. 이 규칙은 이용자가 보던 시간·비용이 조용히 바뀌는 것을 막고, 운영자 변경 이력을 분명하게 남긴다.

일반 사용자는 Slot 자체를 예약하는 화면을 보지 않는다. `AVAILABLE`이면 온보딩을 마친 일반 회원에게만 `[이 시간으로 세션 열기]`를 보여 준다. `ALLOCATED`이면 연결된 `PARTNER_COURT` Match를 보여 주고, 참가자는 그 세션에만 참가 신청할 수 있다. `ENDED`, `BLOCKED`, `CANCELLED`는 상태와 최신 갱신 시각만 읽을 수 있고 CTA는 제공하지 않는다. 예약 요청·가격 결제·운영자 승인 대기 단계를 노출하지 않는다.

세션 모집자가 시작 전 Match를 취소하면 Match와 연결 신청만 `CANCELLED`로 전환하고, 연결 Slot은 `ALLOCATED`·`PUBLIC`과 상태 이력을 유지한다. 일반 회원에게는 `코트 매칭이 취소됐어요`와 기존 코트 매칭 상세만 읽기 전용으로 보이며, 세션 개설·참가 신청 CTA를 제공하지 않는다. 이 Slot을 자동으로 다시 열지 않는다. 운영자만 실제 공급 가능 여부를 확인한 뒤 취소된 Match가 연결된 Slot을 명시적으로 `BLOCKED`로 중지할 수 있고, 그 뒤에야 같은 시간의 새 `DRAFT`를 만들 수 있다. 이 중지는 공급 철회 Incident, 운영자 제한, 새 Match 취소를 만들지 않는다.

### 4.4 중복 배정은 서버에서 막는다

동일한 CourtSlot은 활성 Partner Court Match 하나에만 연결한다. 카드에서 숨기는 것만으로 막지 않고 `AVAILABLE → ALLOCATED` 전환과 Match 생성을 하나의 트랜잭션으로 처리한다. 충돌 시 사용자는 `이 코트 시간대는 이미 다른 코트 매칭에 연결됐어요.`를 본다.

### 4.5 결제와 비용 안내를 구분한다

Pilot은 앱 결제를 제공하지 않는다. Slot의 금액은 게스트 한 명이 내는 **고정 참가비**다. 코트 한 면의 총액이 아니므로 인원으로 나누지 않고, `예상 1인 비용` 같은 추정 표현도 쓰지 않는다. 일반 매칭의 게스트 참가비와 같은 모델이라 두 코트 출처의 비용 문구가 같다. 카드·상세·신청 화면에 결제 완료, 환불, 정산처럼 보이는 문구를 쓰지 않는다.

## 6. 전체 흐름

### 6.1 운영자 등록과 시간 공급

flowchart TD

    C --> D["사업자·주소·장소 확인"]

## 7. 상태와 사용자 문구

### 7.1 CourtSlot

| 상태 | 의미 | 공개 상태 문구·일반 사용자 행동 | 운영자 문구 |
| --- | --- | --- | --- |
| `DRAFT` | 작성·수정 중 | 비공개 | 초안 작성 중 |
| `AVAILABLE` | 세션 개설에 연결 가능 | 칩 `열기 가능` · 제목 `코트 매칭을 열 수 있어요` · 온보딩 완료 회원만 개설 CTA | 모집 가능한 시간 |
| `ALLOCATED` | 하나의 Partner Court Match에 연결됨 | 연결 Match 상태를 `모집 중`·`모집 마감`·`취소됨`으로 표시하고, 제목·모집자·남은 자리 요약과 함께 상세로 이동. 취소된 코트 매칭은 읽기 전용 | 세션 사용 중 또는 운영자 확인 대기 |
| `ENDED` | 이용 시간이 지남 | 칩 `이용 완료` · 목록에서 제외하고 상세에서만 읽기 전용 | 이용 완료 |
| `BLOCKED` | 운영상 새 세션 연결 중지 | 칩 `연결 중지` · 제목 `새 코트 매칭 연결이 중지됐어요` · 읽기 전용 | 공개 중지 · 새 초안으로 정정 |
| `CANCELLED` | 연결된 시간의 공급이 철회됨 | 칩 `취소됨` · 제목 `코트 매칭이 취소됐어요` · 읽기 전용 | 긴급 공급 철회 후 검토 중 |

`AVAILABLE`은 참가자에게 직접 보이는 “예약 가능” 상태가 아니다. 공개 Slot은 `PUBLIC` 상태를 유지해도 예약할 수 없으며, 세션을 열거나 연결된 Match를 보는 행동만 가능하다. `ALLOCATED` 카드에는 연결된 Match의 `OPEN`, `CLOSED`, `COMPLETED`, `EXPIRED`, `CANCELLED`를 사람이 이해할 수 있는 상태로 우선 표시한다.

### 7.2 Match와 MatchApplication

Partner Court Match는 기존 상태를 그대로 사용한다.

| 도메인 | 상태 | 책임자 |
| --- | --- | --- |
| Match | `OPEN`, `CLOSED`, `COMPLETED`, `EXPIRED`, `CANCELLED` | 세션 모집자·자동 상태 작업 |
| MatchApplication | `PENDING`, `ACCEPTED`, `REJECTED`, `WITHDRAWN`, `CANCELLED` | 세션 모집자, 참가자, 자동 상태 작업 |

운영자의 CourtSlot 상태는 MatchApplication 상태를 바꾸지 않으며, MatchApplication 수락은 CourtSlot 상태를 바꾸지 않는다.

## 8. OP01·OP02 운영자 등록과 심사 상태

### 8.1 OP01 운영자 등록

목적은 코트 시간을 공급할 실제 운영 권한을 확인하는 것이다. 입력 항목·검증·개인정보 보호는 `02-prd.md` 3.2와 `04-erd.md` 13.1을 따른다.

- 사업자등록번호·개업일·대표자명으로 사업자 상태를 확인한다.
- 사업자명, 테니스장 이름·주소와 **사업자등록증 1부**를 심사 제출의 필수 입력으로 받는다. 파일은 PDF·JPEG·PNG만, 10 MiB 이하만 허용한다.
- OP01은 `사업자 정보 → 테니스장 정보 → 사업자등록증 제출`의 3단계다. 등록증을 아직 올리지 않았거나 서버가 신청자 소유의 대기 파일로 확인하지 못하면 제출 CTA를 비활성화하고 서버도 `422 BUSINESS_REGISTRATION_CERTIFICATE_REQUIRED`를 반환한다.
- 등록증 파일명·객체 URL·원문은 운영자 화면, 목록 응답, 분석 이벤트에 표시하지 않는다. 업로드 완료 여부와 안전한 안내만 보여 준다.
- 표준 도로명주소·장소 검색으로 테니스장 존재·일치를 보조 확인한다.
- 사업자 유효만으로 운영 권한을 승인하지 않는다.
- 지점·위탁·공공시설·명의 변경·동일 장소 중복은 등록증과 별도의 운영 권한 증빙 또는 시설 담당 연락처로 조건부 검토한다. 이를 모든 신청자에게 일괄 업로드하게 하거나 자유 형식 자료실을 만들지 않는다.
- 운영자 휴대폰 번호는 심사 결과 안내를 위해 선제 수집하지 않는다. 문자·카카오 알림 계약과 고지 전에는 OP01에 표시하지 않는다.
- 외부 확인 불가는 재시도 후 검토·수정 경로로 안내하며 단순 불일치를 즉시 영구 반려하지 않는다.

### 8.2 OP02 운영자 심사 상태

| 상태 | 안내 | CTA |
| --- | --- | --- |
| 자동 확인 중 | 사업자와 테니스장 정보를 확인하고 있어요 | 잠시 기다리기 |
| 코트 초안 작성 가능 | 코트와 시간을 먼저 준비할 수 있어요. 아직 세션에 연결할 수 없어요 | 코트 초안 만들기 |
| 검토 필요 | 테니스장 또는 운영 권한을 한 번 더 확인해 주세요 | 정보 수정·추가 확인 |
| 보완 필요 | 추가 정보가 필요해요 | 정보 보완하기 |
| 승인 | 운영자 등록이 완료됐어요. 이제 시간을 공개할 수 있어요 | 운영자 홈으로 |
| 공개 일시 중지 | 새 세션에 연결하기 전에 정보를 다시 확인해야 해요 | 확인 내용 보기 |

`PUBLISH_APPROVED` 전에는 코트·시간 초안 저장만 가능하며 이용자 공개, 세션 연결, 운영자 메뉴의 운영 데이터 노출을 허용하지 않는다.

### 8.3 IR01 내부 심사와 판정

내부 심사자는 일반 코트 운영자와 다른 `INTERNAL_REVIEWER` 역할이다. 자신의 신청은 목록·판정 API 모두에서 거절하며, 운영자에게 참가 신청 수락이나 코트 예약 승인 권한을 주지 않는다.

- 목록은 기본적으로 `REVIEW_REQUIRED` 신청만 시간순으로 보여 주며, 심사자는 `PUBLISH_APPROVED`와 `SUSPENDED` 목록도 별도 탭에서 조회할 수 있다.
- 심사자는 승인, 정보 보완 요청, 반려 중 하나와 선택형 안전 사유 코드를 고른다. 자유 메모와 증빙 원문을 감사 이력에 넣지 않는다.
- 심사자는 목록의 안전한 요약에서만 사업자등록증 열람을 시작할 수 있다. 서버가 `INTERNAL_REVIEWER` 권한과 연결된 `ATTACHED` 증빙을 확인한 별도 읽기 경로로만 원문을 전송하며, 공개 URL·다운로드 이력 원문·파일명은 반환하지 않는다.
- 승인은 필수 사업자등록증이 연결돼 있고 별도 승인된 내부 절차에서 사업자·장소·운영 권한을 확인한 경우에만 `PUBLISH_APPROVED`로 전환한다. 서버는 같은 정규화 장소의 다른 승인 신청이 없는지 트랜잭션 안에서 다시 확인한다.
- 보완 요청과 반려는 각각 `CHANGES_REQUESTED`, `REJECTED`로 전환한다. 판정, 사유 코드, 심사자, 시각은 변경 불가 감사 이력으로 남기며 운영자 DTO에는 반환하지 않는다.
- `REVIEW_REQUIRED`가 아닌 신청을 다시 판정하거나 두 심사자가 동시에 같은 신청을 판정하면 한 요청만 성공하고 다른 요청은 최신 상태를 다시 확인하도록 안내한다.
- 공개 승인 운영자는 `SUSPENDED`로만 전환한다. 심사자는 사업자·장소·운영 권한 재확인, 안전 검토, 시설 폐쇄 중 선택형 사유를 고르며 자유 메모를 남기지 않는다. 중지는 새 Slot 공개·새 세션 연결·사진 관리와 공개 Slot·사진 노출을 즉시 막지만, 이미 연결된 Match와 신청은 자동 취소하지 않는다.
- 심사자는 `PUBLISH_APPROVED` 운영자의 현재 `ACTIVE` Court도 별도로 `INACTIVE`로 전환할 수 있다. Court 비활성화는 해당 시설의 새 공급·사진 공개만 막고, 운영자 신청 자체를 반려하거나 기존 세션을 취소하지 않는다. 두 조치 모두 Court 사진을 30일 뒤 정리 대상으로 예약하고, 심사자·선택형 사유·시각을 변경 불가 이력으로 남긴다.

## 9. 운영자 시간 관리

### 9.1 OP03 운영자 홈

운영자가 우선 확인할 정보는 다음 순서다.

1. 오늘 사용 중인 제휴 코트 세션 수
2. 앞으로 모집 가능한 시간 수
3. 공개 중지, 긴급 공급 철회 또는 검토가 필요한 시간
4. 빠른 시간 등록 CTA

카드 예시:

- `오늘 세션 사용 중 2개`
- `이번 주 모집 가능한 시간 8개`
- `확인이 필요한 시간 1개`

참가 신청 대기 수, 참가자 실력, 예약 승인 CTA, 매출·정산 정보는 표시하지 않는다.

### 9.2 OP04 코트 목록·관리

CourtCard에는 코트장 이름, 코트 면 수, 실내·실외, 바닥, 운영 상태와 앞으로 등록한 시간 수를 표시한다. 한 운영자 신청은 한 시설에만 적용한다. 다른 지점·주소를 추가하려면 OP01 검증을 새로 시작하게 한다.

### 9.2.1 OP07 대표 코트 사진

`PUBLISH_APPROVED` 운영자는 자신의 승인된 시설 사진만 최대 3장 올리고, 그중 1장을 대표로 선택한다. 운영자 홈의 `[대표 코트 사진 관리]`에서 진입하며, 시설 사진이 아직 없으면 기본 코트 일러스트가 계속 표시된다.

- 허용 형식은 JPEG·PNG·WebP이고 파일당 최대 10 MiB다. 브라우저 `accept` 안내와 별개로 서버가 MIME 타입·크기·바이너리 시그니처를 확인한다.
- 인물 얼굴, 연락처, 예약번호, 사업자등록증이나 예약 확인서가 보이는 사진은 올리지 않는다. 외부 웹·지도 사진을 자동 수집하지 않고, 운영자가 직접 제공하거나 사용할 권한이 있는 사진만 쓴다.
- 사진을 고른 뒤 `[사진 저장하기]`로 연결을 확정한다. 저장하지 않은 업로드는 이용자에게 보이지 않으며 24시간 뒤 삭제한다. 사진을 지우거나 저장 중 기존 사진을 교체하면 해당 파일은 즉시 공개에서 제외되고 다음 정리 작업에서 삭제한다.
- 대표 사진은 CP01 공개 Slot 카드·상세 및 연결된 CP02 Match의 상단에만 `운영자 제공 사진`으로 보인다. 사진은 예약 가능, 운영자 심사, Rally On의 시설 보증을 뜻하지 않는다.
- 내부 심사자가 Court를 비활성화하거나 운영자 공개 승인을 일시 중지하면 사진은 즉시 보호된 공개 경로에서 제외된다. 연결 사진의 `expiresAt`은 30일 뒤로 설정해 보관 후 삭제한다. 이는 운영자 화면의 사진 삭제와 달리 심사 기록을 위한 지연 삭제이며, 실제 공급 불가의 세션 취소를 대신하지 않는다.

### 9.3 OP05·OP06 모집 가능한 시간 관리

SlotCard에는 코트, 시작·종료 시각, 이용 시간, 게스트 참가비, 공개 여부, CourtSlot 상태, 연결된 세션 제목과 상태 변경 시각만 표시한다. 참가자 정보는 표시하지 않는다.

시간 등록 필드:

- 코트 면, 날짜, 시작 시간, 이용 시간
- 게스트 참가비(게스트 1인이 내는 고정 금액), 이용 조건, 준비물·현장 안내
- 공개 여부

| Slot 상태 | 수정 가능 범위 |
| --- | --- |
| `DRAFT` | 전체 수정·취소 가능 |
| `AVAILABLE` | 직접 수정 불가. `공개 중지` 후 같은 조건을 새 초안으로 등록 |
| `ALLOCATED` | 시간·가격·코트·정원·이용 안내 직접 수정 불가. 연결된 세션 보기 또는 운영상 문제 접수. 단, 연결 Match가 모집자 취소로 `CANCELLED`이면 운영자 확인 후 `BLOCKED`로 중지하고 새 초안을 등록 |
| `BLOCKED` | 읽기 전용. 재공개하지 않고 새 초안으로 정정 |
| `ENDED`, `CANCELLED` | 읽기 전용 |

같은 CourtUnit의 활성 시간은 겹치게 등록할 수 없다. 클라이언트 안내와 별개로 서버·DB가 최종 판단한다.

### 9.4 운영상 문제 접수와 긴급 공급 철회

`ALLOCATED` Slot에서 운영자는 참가자에게 직접 연락하거나 시간을 바꾸지 않는다. 카드의 `[운영상 문제 접수]`은 다음 두 흐름을 명확히 분리한다.

1. 일반 오류·문의: `시간 정보를 바로 바꿀 수 없어요. 운영 검토에 접수할게요.`를 보여 주고, Match·Slot 상태는 바꾸지 않는다.
2. 실제 공급 불가: `시설 폐쇄`, `안전 위험`, `재난`, `등록한 시간이 실제로 불가함` 중 하나를 선택하고 한 번 더 확인한다. 서버는 Slot을 `CANCELLED`, 연결 Match를 `CANCELLED`로 바꾸며 안전한 인앱 안내를 만든다.

긴급 철회 확인 화면에는 `연결된 세션이 취소되고 모집자와 신청자에게 앱 안에서 안내돼요. 시간을 다른 때로 바꾸는 기능은 아니에요.`를 고정 표시한다. 운영자 귀책 긴급 철회가 최근 30일 2회 또는 시작 24시간 이내 1회이면, 운영 홈에는 `새 시간 공개가 일시 중지됐어요`를 표시하고 새 공개 CTA를 막는다. 이미 연결된 다른 세션은 이 제한만으로 취소하지 않는다.

## 10. CP01 코트 매칭 탐색

### 10.1 목적과 진입

초보자가 코트 예약을 고민하지 않고, 이미 준비된 시간과 비슷한 메이트를 한 번에 이해해 참가할 수 있게 한다. 하단 `코트 매칭` 메뉴, 매칭 탭의 Partner Court 필터, 추천 카드, `/partner-sessions`에서 진입한다. `코트 매칭`은 일반 사용자의 코트 예약 메뉴가 아니라 운영자가 공개한 시간 목록임을 화면 설명에 함께 알린다.

### 10.2 화면 구성

1. 제목: `코트 걱정 없이 함께 테니스해요`
2. 보조 문구: `운영자가 준비한 코트 시간에 나와 비슷한 메이트와 함께해요.`
3. 섹션 제목: `다가오는 코트 매칭`
4. 대표 코트 사진 또는 기본 일러스트와 공개 상태가 있는 PartnerSessionCard 또는 PublicSlotCard 목록
5. 안내: `참가 신청은 코트 매칭을 연 모집자에게 보내요.`

Figma CP01의 첫 카드 예시는 다음을 표시한다.

- 대표 코트 사진과 출처 `운영자 제공 사진` — 사진이 없으면 Rally On 기본 코트 일러스트. 제휴 코트라는 사실은 별도 배지로 알리지 않는다. 화면 자체가 운영자가 공개한 시간 목록이고, 상단 설명이 이미 그 맥락을 준다.
- 상태 칩 `모집 중`
- 제목 `편하게 랠리해요`
- `8월 28일 목요일 · 오후 7:00 · 2시간`
- `마포 테니스파크 · 2번 코트`
- `민지님이 같이 칠 메이트를 찾고 있어요.`
- `3명 더 함께할 수 있어요`
- `자세히 보기 →`

`ALLOCATED` 카드는 연결된 Match의 제목, `{모집자}님이 같이 칠 메이트를 찾고 있어요.`, 남은 자리, 원하는 플레이, 초보자 환영 여부를 함께 보여 준다. 참가비는 Slot에 고정된 값이라 모집 상태와 무관하게 같은 금액을 보여 준다. 운영자 화면의 SlotCard에는 이 모집 요약을 넣지 않는다(§9.3).

`예약 가능`, 운영자 이름, 운영자 승인 여부, 결제 버튼은 카드에 표시하지 않는다. `AVAILABLE` 상태의 PublicSlotCard에는 `세션을 열 수 있어요`와 `[이 시간으로 세션 열기]`만 표시하며, 참가 신청 CTA는 표시하지 않는다. `ENDED`, `BLOCKED`, `CANCELLED` 카드에는 상태와 갱신 시각만 표시한다.

`/partner-sessions`는 아직 끝나지 않은 공개 Slot만 시간순으로 보여 준다. 이미 지난 시간은 목록에서 빼고, 상태·갱신 시각이 필요하면 상세 경로에서 읽는다. 저장된 대표 사진이 있으면 보호된 읽기 경로를 통해 `운영자 제공 사진` 출처와 함께 표시하고, 없으면 기본 일러스트를 표시한다. 사진이 없다는 사실이나 사진 자체를 예약 가능 여부·서비스 보증으로 해석하게 하지 않는다. 카드 상세는 `/partner-sessions/{slotId}`에서 같은 안전한 공급 상태·코트·시각·비용·현장 정원을 다시 보여 준다. `ALLOCATED` 카드만 연결된 Match 상세로 이동하고, `AVAILABLE` 카드만 CP03으로 이동한다.

### 10.3 빈 화면과 오류

빈 화면:

> 지금 참여할 수 있는 코트 매칭이 없어요.
>
> 다른 지역이나 날짜의 매칭도 살펴보세요.

CTA는 `[일반 매칭 둘러보기]`다. 오류 시 기존 필터를 유지하고 `[다시 불러오기]`를 제공한다.

## 11. CP02 제휴 코트 세션 상세와 참가 신청

CP02는 기존 S04 Match 상세를 확장한다. 정보 순서는 다음과 같다.

1. 대표 코트 사진과 `운영자 제공 사진` 출처, 사진이 없을 때 기본 코트 일러스트
2. (배지 없음) 제휴 코트라는 사실 자체는 상세에서 따로 배지로 알리지 않는다. 참가 신청 흐름도 비용 모델도 직접 예약 매칭과 완전히 같아서, 참가자가 구분해야 할 것이 없다. 코트가 어디서 왔는지는 사진의 `운영자 제공 사진` 출처와 `현장 이용 안내`가 자연스럽게 알려 준다.
3. 제목, 원하는 플레이, 초보자 환영 여부, 모집자 요약
4. 날짜·시간·이용 시간
5. 코트장·코트 면·주소·이용 안내
6. 게스트 참가비와 추가 비용 안내
7. 남은 자리
8. `참가 신청은 코트 매칭을 연 모집자에게 보내요.`
9. 하단 고정 `[참가 신청하기]`

하단 CTA는 기존 MatchApplication 바텀시트로 이어진다. 로그인·온보딩 미완료, 본인 세션, 마감, 취소·종료 상태는 Core S04와 같은 권한·오류 상태를 따른다.

운영자에게 직접 보내는 연락, 코트 예약 요청, 운영자 승인 대기는 제공하지 않는다. 게스트 참가비는 앱에서 결제하지 않는다는 안내를 필요한 곳에 짧게 표시한다.

## 12. CP03 제휴 코트 세션 열기

CP03은 일반 모집자가 `AVAILABLE` Slot을 선택한 뒤 기존 S05 매칭 등록에 진입하는 흐름이다.

### 12.1 사전 조건

- 로그인과 일반 테니스 프로필 온보딩 완료
- `PUBLISH_APPROVED` 운영자가 공개한 `AVAILABLE` Slot
- 시작 시각 이전
- 선택 시점에 다른 Partner Court Match와 연결되지 않음

### 12.2 고정·입력 필드

| 구분 | 필드 |
| --- | --- |
| Slot에서 고정 | 코트장·코트 면, 주소, 시작·종료, 게스트 참가비, 이용 안내 |
| 모집자가 입력 | 게임 유형, 모집 인원(게임 유형이 복식이면 남녀별 인원), 원하는 플레이, 원하는 상대, 짧은 소개(선택), 정산 정보(선택). 제목은 서버가 코트 이름으로 자동 생성한다. Match 연락은 수락 뒤 생성되는 서비스 내 방에서만 처리 |
| 서버 계산 | `courtSource = PARTNER_COURT`, `courtSlotId`, Match 상태. 참가비는 Slot 값을 그대로 옮기며 계산하지 않는다 |

제출 CTA는 `[미리보기]`이고, 미리보기 시트 안의 `[이 시간으로 코트 매칭 열기]`에서만 실제 개설이 일어난다. 입력 항목과 검증은 일반 매칭 개설(S05)과 같은 구성을 쓴다. 사용자는 코트를 개인적으로 예약한 것으로 표현하지 않는다.

### 12.3 충돌과 성공

서버가 Slot을 확보하지 못하면 입력값을 유지하고 다른 시간을 고르게 한다. 성공 시에는 새 Match 상세로 이동하고, 카드·상세 모두 Partner Court 배지를 표시한다.

- 사업자·대표자·증빙 원문과 외부 API 응답은 화면·분석 이벤트·로그에 노출하지 않는다. 미연결 증빙은 24시간, 심사에 연결된 사업자등록증은 최대 30일 또는 승인·반려 뒤 다음 정리 작업까지 보관한 후 비공개 객체와 메타데이터를 함께 삭제한다.

## 15. 구현 인수 체크리스트

### 범위와 권한

- [ ] 일반 사용자 CourtBooking, 예약 요청·승인·예약 목록을 구현하지 않는다.
- [ ] 운영자가 참가 신청을 수락·거절할 수 없다.
- [ ] 세션 모집자만 MatchApplication을 수락·거절할 수 있다.
- [ ] 참가자는 운영자에게 직접 예약을 요청할 수 없다.

### 시간 공급과 세션

- [ ] `PUBLISH_APPROVED` 운영자만 Slot을 공개한다.
- [ ] 동일 CourtUnit의 활성 시간이 겹치지 않는다.
- [ ] 동일 Slot이 활성 Partner Court Match 두 개에 연결되지 않는다.
- [ ] Slot 배정과 Match 생성이 하나의 서버 트랜잭션으로 완료된다.
- [ ] `PARTNER_COURT` Match의 코트·시간·비용은 연결 Slot에서만 읽고 모집자가 임의로 바꾸지 못한다.
- [ ] 공개 여부와 Slot 공급 상태를 분리하고, 상태가 바뀌어도 초안 외 Slot은 공개 상태를 유지할 수 있다.
- [ ] 공개 Slot의 사용자 표시 필드는 수정·재공개할 수 없고, 정정은 공개 중지 후 새 초안으로만 한다.
- [ ] `ALLOCATED` Slot의 공급 철회는 사유 코드·감사 이력·연결 Match 취소·대상 인앱 안내를 하나의 서버 작업으로 처리한다.
- [ ] 세션 모집자 취소는 연결 Slot을 자동 재공개하지 않으며, 취소된 Match 연결을 확인한 운영자만 `BLOCKED` 처리 후 새 초안을 만들 수 있다.
- [ ] 반복 철회 제한은 새 공개만 막고, 다른 연결 세션이나 참가 신청 권한을 임의로 바꾸지 않는다.

### 사용자 경험

- [ ] CP01·CP02는 “예약”이 아니라 “코트 매칭” 언어를 사용한다.
- [ ] 공개 Slot에는 사람이 이해할 수 있는 현재 상태와 상태 변경 시각을 보이고, 상태에 맞지 않는 CTA를 숨긴다.
- [ ] CP02의 하단 CTA는 `참가 신청하기`이며 기존 신청 흐름을 사용한다.
- [ ] 제휴 코트 배지는 쓰지 않는다. CP01은 화면 자체가 운영자 공개 시간 목록이고, CP02는 비용 문구·사진 출처·현장 이용 안내로 구분한다.
- [ ] 결제·환불·정산을 암시하는 CTA가 없다.
- [ ] 로딩, 빈 화면, 로그인·온보딩 미완료, Slot 충돌, 마감·취소 오류가 처리된다.

## 16. 구현 전 확정할 항목

다음 정책은 이번 설계에서 확정한다.

1. 공개 Slot은 직접 수정·재공개하지 않는다. 정정은 `BLOCKED`와 새 `DRAFT`로 처리한다.
2. `ALLOCATED` Slot은 일반 수정·중지가 불가능하다. 실제 공급 불가만 긴급 철회할 수 있고, Slot·Match 취소와 인앱 안내·감사 이력을 묶는다.
3. 한 Slot에는 활성 Partner Court Match 한 건만 허용한다.
4. 운영자 귀책 긴급 철회가 최근 30일 2회 또는 시작 24시간 이내 1회면 새 공개를 자동 중지하고, 운영 검토 후에만 해제한다.
5. 인앱 안내는 Match 상세·활동 화면에서 제공한다. 푸시·문자·카카오 알림의 즉시 전달은 별도 동의·계약 범위다.
6. 세션 모집자의 시작 전 취소는 Slot을 자동 재공개하지 않는다. 운영자가 실제 공급 가능 여부를 확인한 뒤 취소된 Match 연결 Slot만 `BLOCKED`로 중지하고, 새 `DRAFT`를 만들어 공개한다.
7. 대표 코트 사진은 공개 승인 운영자가 최대 3장만 관리하고 대표 1장만 노출한다. 미연결 파일은 24시간, 제거·교체 파일은 즉시 정리한다. 아직 존재하지 않는 Court 비활성화·승인 취소 전환이 추가되면 사진을 30일 뒤 삭제한다.

아래 항목은 Commerce 또는 사진 수직 단위에 영향을 주므로 여전히 별도 확정이 필요하다.

- 운영자가 Slot 비용을 0원으로 등록할 수 있는지와 앱 밖 납부가 필요한 유료 Pilot의 수령 주체·시점·문의 창구
- 운영자 사진의 신고·권리 침해 처리 절차

### 16.1 이용자·운영자 사이의 Pilot 운영 이슈

| 이슈 | 왜 문제가 되는가 | Pilot의 최소 보호책 | 구현 전 확정 필요 |
| --- | --- | --- | --- |
| 공개 Slot을 예약으로 오해 | `AVAILABLE`만 보고 참가자가 운영자에게 예약을 기대할 수 있음 | 공개 상태와 CTA를 분리. `AVAILABLE`은 세션 개설만, `ALLOCATED`는 연결 세션 참가 신청만 허용 | 아니요 — 이 문서의 기본 정책 |
| 상태가 오래됨 | 운영자가 코트를 더 이상 제공하지 않는데 이전 시간·세션 정보가 남으면 현장 혼선이 생김 | 상태 칩·`statusChangedAt`·상태 이력, 공개 후 직접 수정 금지 | 상태 변경 SLA와 외부 긴급 안내 채널 |
| 현장 인원·전환 시간 불일치 | 모집자가 코트 수용 인원보다 많이 모으거나, 앞뒤 세션이 겹쳐 이용 불가 | Slot별 현장 최대 인원 검증, CourtUnit 시간 겹침 방지 | 코트별 최대 인원, 입장·정리 버퍼 기준 |
| 세션 모집자 또는 운영자 취소 | 이미 수락된 참가자는 갈 곳을 잃고, 운영자는 빈 시간을 다시 공급하지 못할 수 있음 | 모집자 취소는 자동 재공개 없이 Slot·Match 이력을 남기고, 운영자 확인 후 `BLOCKED`와 새 `DRAFT`만 허용. 운영자 철회는 긴급 사유 코드·상태 이력·연결 Match 취소·인앱 안내로만 처리 | 외부 긴급 알림·보상/문의 절차 |
| 현장 확인과 개인정보 | 운영자는 현장 이용자를 확인할 필요가 있지만 참가자의 연락처·프로필을 모두 볼 필요는 없음 | 운영자는 참가 신청·프로필을 보지 않는다 | 세션 대표자 확인 방식(예: 일회성 방문 코드)과 운영자–대표자 최소 연락 경로 |
| 코트 비용의 수납 책임 | 결제가 없으면 운영자가 누구에게 어떤 방식으로 비용을 받는지, 참가자가 누구에게 정산하는지 불명확함 | 앱에 결제·환불·정산 문구를 두지 않고 비용은 참고값으로만 표시 | **필수:** 무료 Pilot인지, 모집자 또는 참가자가 앱 밖에서 누구에게 어떤 방식으로 납부하는지 |
| 노쇼·파손·규정 위반 | 운영자에게는 현장 책임 주체가 필요하고, 참가자에게는 과도한 개인 책임 전가 위험이 있음 | 이용 규칙을 Slot에 고정하고, 운영자는 신청 수락 권한을 갖지 않음 | **필수:** 현장 대표 책임자, 노쇼·파손·민원 처리 주체와 운영 문의 절차 |

위 표의 **필수** 항목은 결제 기능을 추가하자는 뜻이 아니다. 비용·현장 책임이 확정되지 않은 경우에는 더 단순하게 `운영자 부담의 무료 체험 시간`만으로 Pilot을 시작하는 것이 안전하다. 유료 시간대를 포함하려면 앱 밖 납부의 수령 주체·시점·환불 문의 창구를 화면과 운영 절차에 분명히 해야 한다.

## 18. Court Commerce 후속 화면 원칙

이 절은 Pilot 화면을 결제 화면으로 전환하는 구현 지시가 아니다. 아래 표의 `코트 총액`·`예상 1인 부담`은 Commerce 단계에서 다시 검토할 별도 모델이며, Pilot의 고정 게스트 참가비(§4.5)와 충돌하는 채로 남겨 둔다. Commerce 구현 게이트가 닫힌 뒤에 추가할 화면 상태의 기준이며, 상세 정책은 `07-court-commerce-design.md`를 따른다.

| 흐름 | 사용자에게 보여 줄 핵심 | 유지할 경계 |
| --- | --- | --- |
| 유료 Slot으로 세션 개설 | 코트 이용 총액 한 건, 최소 인원, `무료 취소: 정확한 시각`, 현장 자율 분담 안내, 15분 결제 기한 | `1인 참가비 결제`, `코트 예약`·운영자 승인 CTA를 만들지 않음 |
| 유료 Match 참가 신청 | 코트 총액, 목표 인원 기준 예상 1인 부담, `모집자가 코트 이용료를 결제했어요`, `현장에서 함께 정산해요` | 참가자 결제 버튼·결제 초대·영수증·미납 상태를 만들지 않음 |
| 최소 인원 미달 | 현재 수락 인원, 모집자의 `현재 인원으로 진행` 또는 `전액 취소` CTA, 취소 마감 정확한 시각 | 참가자에게 비용을 청구·환불하는 CTA를 만들지 않음 |
| 공급 철회 취소 | 안전한 취소 안내, 모집자에게 `환불을 진행하고 있어요`, 최종 환불 상태 | 운영자 연락처·수기 이체·원문 철회 사유를 노출하지 않음 |
| 운영자 Commerce | PG 온보딩 상태, 요금표 버전, 플랫폼 수수료 무료 기간 종료 시각, 모집자 결제 기준 정산 요약 | 참가 신청 승인·참가자의 카드/계좌/현장 정산 정보를 제공하지 않음 |

공통 원칙은 다음과 같다.

- 유료 Slot에는 코트 이용 총액을 우선 표시하고, 목표 인원 기준 `예상 1인 부담`은 참고값임을 함께 표시한다. 운영자가 1인 가격을 입력하거나 참가자에게 앱 결제를 청구하지 않는다.
- PG 리다이렉트 복귀만으로 결제 완료를 단정하지 않고, 서버가 승인 상태를 확인하는 로딩·오류 화면을 둔다.
- 모집자에게만 코트 이용 총액을 청구한다. 참가자 현장 비용 분담은 서비스가 수납·환불·미납 보장하지 않는다는 문구와, 24시간 전 전액 취소의 정확한 마감 시각을 함께 보인다.
- 모바일 390×844, Noto Sans KR, 기존 하드코트 블루·테니스볼 옐로, 로딩·빈 화면·접근성 패턴을 유지한다.
- Figma 사용량 한도가 해제된 뒤 사용자가 명시적으로 요청할 때만 Commerce 화면을 Figma에 동기화한다.
