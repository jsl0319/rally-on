# iPhone 화면 크기·첫 진입 개선 · 2026-10-10

## 문제와 범위

사용자의 iPhone 영상에서 첫 화면 아래 안내가 접히고 이미지와 혜택 사이 여백이 벌어졌다. PC에서 잘 보인다고 실제 앱에서도 맞는다고 볼 수 없었다. 초록·아이보리는 유지한다. 신규 인증·의존성·개인정보·입금/환불 정책을 추가하지 않고 기존 UI와 로그인 진입 연결만 수정한다. native/Claude 작업은 보존한다.

## 후속 결정: 간결한 브랜드 진입 화면

사용자가 추가로 제공한 smaxh·테니스프렌즈·ON.COURT 진입 화면을 참고해 첫 화면을 더 단순화한다. 이 결정은 아래 초기안의 일러스트·세 가지 혜택 유지 및 로그인 로고 제거 결정을 대체한다. 다른 화면에서 반복 로고를 제거한 결정과 안전 영역 수정은 유지한다.

- 참고한 것은 서비스명과 짧은 취지의 중앙 배치, 아래에 모인 소셜 로그인 행동이다. 타 서비스 로고·색·문구를 복제하지 않는다.
- `Rally On` 워드마크, `부담 없이, 함께 테니스.` 슬로건, `나와 비슷한 메이트를 만나요.` 설명을 표시한다. 큰 일러스트와 혜택 3열은 첫 화면에서 제거한다.
- 하단에는 카카오 시작, Apple 시작, `테니스장을 운영하고 계신가요?`, 약관 링크 순으로 배치한다. 카카오·Apple 버튼 높이는 최소 54px, 운영자 링크 터치 높이는 최소 44px이다.
- Apple은 사용자 요청에 따라 미리 배치한 비활성 버튼이다. `준비 중`을 표시하고 실제 인증 요청은 연결하지 않는다. 카카오의 로딩·오류·사용자/운영자 콜백은 유지한다.
- 준비된 기능처럼 보이는 Google 로그인, 최근 로그인 배지, 국가 선택은 추가하지 않는다. 기존 의존성의 아이콘·CSS·인라인 SVG만 사용한다.
- flex의 남는 공간으로 브랜드 영역을 배치하고 버튼은 정상 문서 흐름 안에 둔다. 짧은 화면·오류 표시·글자 확대 시 내용이 잘리지 않도록 스크롤을 허용한다.

### 로고·배경 후속 조정

- 사용자 요청에 따라 소문자 `rally on`에서 R·O를 대문자로 표기한 `Rally On`으로 변경한다. O는 별도 장식 공을 덧붙이는 대신 글자 자리에 라임색 테니스공을 넣는다. 작은 화면에서도 선명한 벡터로 제작하며 화면 읽기 이름은 `Rally On`을 유지한다.
- 이탤릭·900 굵기와 위로 3도 기울기로 운동 서비스의 경쾌함을 표현한다. 자동 애니메이션은 없다.
- 단색 아이보리 배경을 옅은 그린 그라데이션으로 바꾸고 낮은 대비의 대각선 코트 라인을 더한다. 장식은 클릭·포커스를 받지 않으며 화면 읽기에서 제외한다. 첫 화면의 상단 안전 영역 색상도 맞춘다.
- 브랜드 영역만 조정하며 로그인·Apple 준비 중·운영자 진입·슬로건·약관·서버 정책은 유지한다.
- 이 조정 뒤 린트·타입 검사·빌드·기존 테스트 410개를 다시 통과했다(DB 테스트 110개 제외). 브라우저 320×568·375×728에서 잘림이 없고 1280px에서 콘텐츠 폭 480px를 유지했다. 배포용 로컬 화면의 콘솔 오류는 없으며, 최신 로고·배경의 실제 iPhone 앱 검증은 아직 하지 않았다.

### 후속 첫 화면 검증

- 린트·타입 검사·프로덕션 빌드 통과. 기존 테스트 410개 통과, DB 조건으로 110개 제외.
- 320×568 및 375×728에서 가로 넘침·세로 잘림 없음. 1280px 데스크톱에서 콘텐츠 최대 너비 480px 유지.
- 배포용 로컬 빌드에서 Apple 버튼 비활성·준비 중 표시, 카카오·운영자 버튼 및 약관 링크 노출, 콘솔 오류 없음을 확인.
- 개발 예시 화면의 카카오 시작 버튼에서 프로필 단계로 이동 확인. 실제 카카오 계정 인증을 새로 실행한 검증은 아니다.
- iOS 27 / iPhone 18 Pro 시뮬레이터 Safari에서도 새 워드마크·로그인 두 버튼·운영자 링크·약관이 안전 영역 안에 표시됨을 확인.
- 실제 iPhone 13 mini 앱 검증 및 운영 배포는 아직 수행하지 않았다. HTML 제안서의 시작 화면과 설명도 이번 구성으로 갱신했다.

## 확인한 원인

- 웹 `/`는 `EntrySelection`에서 운영자 콜백을 전달했지만 앱 시작 `/login`의 `M2OnboardingFlow`는 전달하지 않았다. `WelcomeScreen`은 누락을 허용해 운영자 링크 대신 복귀 안내를 표시했다.
- 최소 `100svh` 화면과 WKWebView 자동 inset, 개별 화면 safe-area 여백이 일관되지 않았다. 영상에서 한 화면보다 긴 로그인과 상태 바 아래로 지나가는 콘텐츠를 확인했다. 뷰포트 메타는 기본값에 머물러 있었다.
- 로그인 이미지가 가로폭에 의해 높이가 결정되고, 그 아래 `margin-top:auto`가 남는 세로 공간을 벌렸다. 혜택 세 개와 점 두 개를 다섯 flex 항목으로 분배해 텍스트 길이에 따라 중심이 달랐다.

## 초기 iPhone 개선안 구현 규칙 (첫 화면 구성은 위 후속 결정으로 대체)

- Next의 `viewport` export에 `viewport-fit=cover`를 지정한다. 확대 제한은 추가하지 않는다.
- root body에서 상단 safe-area를 한 번 확보하고 `--rally-screen-height`/`min-h-app`에서 그만큼 뺀다. 온보딩·목록·상세·프로필·운영·오류 화면이 같은 계산을 사용한다.
- 고정된 상단 배경으로 스크롤 내용의 상태 바 겹침을 방지한다. 채팅·개설의 sticky 헤더는 그 아래 붙고 중복 padding은 제거한다. 하단 메뉴/행동의 기존 safe-area는 유지한다.
- 로그인 이미지는 화면 높이에 따라 144–280px로 조절하고 자르지 않는다. 충분한 공간에서는 전체 구성을 중앙 정렬한다. 작은 화면/확대에서도 자연스러운 스크롤을 허용한다.
- 혜택은 세 개의 같은 너비 셀·동일한 아이콘 크기·두 줄 라벨. 로그인 52px, 운영자 진입 44px 터치 영역.
- 운영자 콜백을 필수 prop으로 만들어 다른 진입점에서 다시 누락하기 어렵게 한다. 기존 카카오 인증과 운영자 `/partner/apply` 콜백은 유지한다.
- 로고/슬로건은 로그인·프로필 온보딩·일반 목록·연결 오류에서 제거한다. 법정 안내에 필요한 서비스명과 거래 안내는 유지한다.

안전 영역 구현은 [WebKit의 viewport-fit와 safe-area 안내](https://webkit.org/blog/7929/designing-websites-for-iphone-x/)와 설치된 Next.js `generateViewport`/CSS 문서를 참고했다.

- 브라우저 크기 검사는 실제 iPhone 앱/WKWebView 검사를 대체하지 않는다. 서버 정책과 실계정 금융 동작은 이번 레이아웃 수정의 검증 범위가 아니다.

## iPhone에서 운영 반영 확인

기존 검증 앱의 로컬 생성 설정은 `https://tennis-mate-ochre.vercel.app/`를 원격 서버로, `/login`을 시작 경로로 사용한다. 이번 변경은 웹 UI이므로 운영 배포 후 앱을 완전히 종료하고 다시 열어 확인한다. 로그인 상태가 유지되면 목록부터 보일 수 있으므로 첫 진입 디자인은 로그아웃 후 확인하거나 Safari의 개인정보 보호 탭에서 `/login`을 연다. 네이티브 재서명·재설치와 Claude의 모바일 소스 변경은 이번 배포에 포함하지 않는다. Apple은 계속 준비 중이며 실제 로그인을 제공하지 않는다.

## 2026-10-10 실기기 피드백 후 공통 레이아웃 수정

19:31 영상에서 로그인 화면이 위아래로 움직이며 검은 영역이 드러나고, 운영자 등록 캡처에서 개업일 입력란과 하단 버튼이 오른쪽으로 넘치는 현상을 확인했다. 앞선 데스크톱 모바일 크기 검증만으로는 네이티브 앱까지 검증한 것이 아니었다.

- 웹과 검증 앱은 같은 운영 웹 코드를 사용한다. 다만 기존 iOS 생성 설정은 `contentInset: automatic`이었다. 웹의 `viewport-fit=cover`·safe-area와 함께 사용할 때 네이티브 스크롤 여백까지 더해지는 설정을 없애기 위해 `never`로 변경한다. 웹에서 상하 안전 영역을 한 번만 담당한다. [Capacitor 설정 문서](https://capacitorjs.com/docs/config)를 참고했고 설치된 8.5.3의 `CAPBridgeViewController`가 이 값을 `contentInsetAdjustmentBehavior`로 적용함을 확인했다.
- 화면 최소 높이는 `100dvh - 상단 safe-area`, body는 `min-height:100dvh`로 맞춘다. 작은 화면이나 글자 확대에서 필요한 세로 스크롤과 핀치 확대는 유지한다.
- Safari 날짜 입력의 기본 외형·고유 너비를 명시적으로 정리해 비어 있을 때와 날짜 선택 후 모두 입력 열의 폭을 유지한다. 텍스트 입력은 16px을 유지한다.
- WDS `fullWidth` 버튼 자체에 `fixed`와 좌우 위치를 지정하지 않는다. 공통 `BottomActionBar`가 화면 폭·좌우 20px·하단 안전 영역을 담당하고 내부 버튼은 일반 문서 흐름에 둔다. 운영자 등록·심사 상태·시간 등록·코트 사진에 적용하며, 본문 끝에는 버튼 높이 이상의 스크롤 여유를 둔다.
- 주 메뉴와 운영 화면의 시작 여백을 16px로 줄이고, 뒤로가기와 페이지 제목을 한 줄로 배치한다. 운영자 등록의 불필요한 `COURT PARTNER PILOT` 문구와 큰 진입 여백을 제거한다. 심사에 필요한 입력 항목과 기존 권한·서버 정책은 변경하지 않는다.
- `/layout-preview`는 실제 운영자 표시 컴포넌트를 재사용하는 개발 전용 검사 화면이다. 로컬 상태만 사용하며 API 호출·파일 업로드·운영 데이터 변경 없이 1~3단계를 확인한다. 운영 빌드에서는 404다.

### 네이티브 반영 범위

Claude의 미커밋 모바일 작업 전체를 교체하지 않았다. `mobile/prototype/scripts/configuration.mjs`의 inset 설정 한 곳과 기존 설정 회귀 검증만 수정했다. 생성 설정을 다시 준비하고 iOS 시뮬레이터·기기용 앱을 각각 빌드했다. **이 수정은 웹 새로고침만으로 반영되지 않으며 검증 앱 재설치가 필요하다.** 생성한 기기용 앱은 기존 운영 URL과 `/login` 시작 경로를 그대로 사용한다.
