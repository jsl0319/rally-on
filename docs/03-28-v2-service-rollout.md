# V2 디자인 서비스 전체 적용 · 2026-10-10

## 기준과 완료 범위

사용자는 새 파란색 시안을 취소하고 초록색 V2로 복원한 뒤, 이 디자인을 서비스 전체에 적용하도록 요청했다. `docs/03-27-design-renewal.md`와 `docs/design/rally-on-v2/index.html`의 브랜드·일러스트·화면 위계를 유지한다.

문제는 첫 진입·매칭과 다른 화면 사이의 시각적 불일치다. 기존 기능과 흐름을 유지하면서 참가자·코트 운영자·내부 관리자 화면의 색, 글자, 카드, 입력, 행동과 상태 표시를 같은 기준으로 맞춘다. 새로운 기능이나 의존성, DB·API·권한·추천·입금·취소·환불 정책 변경은 포함하지 않는다. 기존 WDS와 공통 CSS 토큰 확장이 가장 단순한 적용 방식이다.

## 적용 규칙

- 주요 행동: Court green `#174C3C`. 바탕: Warm white `#F7F8F2`. 표면: 흰색. 테니스 라임은 장식·포인트에 한정.
- 카드 20px, 입력/버튼 14px. 카드의 큰 파란 그림자는 제거하고 가는 테두리와 약한 그림자로 통일.
- 페이지 제목 26px/1.35. 채팅방 제목·일정 헤더 등 좁은 내비게이션은 기존 작은 제목을 유지.
- 네이티브 입력 글자 16px, 최소 높이 48px. 주요 버튼·돌아가기의 터치 대상은 최소 44px. 선택·키보드 포커스·오류·처리 중 상태 유지.
- 일반 보조 설명은 회녹색. 처리 완료·주의·오류는 각각 명시적 문구와 상태색을 함께 사용. 게임/플레이 배지의 의미별 색은 유지.
- 상단: 돌아가기/문맥 → 제목 → 필요한 설명. 반복하는 제목성 문구는 줄임. 목록에는 목록·필터·상태를 우선 배치.
- 신청·승인·입금 확인·환불 송금은 서로 다른 상태이며 화면 단순화로 합치지 않음. 원문 고지·금액·계좌·마감·확인 입력을 제거하지 않음.
- WDS reset의 CSS layer 순서는 유지. 컴포넌트 라이브러리 교체 없이 브랜드 토큰 사용.
- V2 개발 미리보기의 절차 예시가 실제 목록 기능으로 오해되지 않게 목록 밖의 설명으로 명시. 실제 코트 목록 하단에 별도 ‘참가까지 세 단계’ 카드를 추가하지 않음.

## 검증 기록

- V2 색·카드·입력·버튼을 참가자, 운영자, 내부 관리 화면에 확장했다. 보조 페이지의 공통 `PageHeader`로 제목·설명·돌아가기를 정리했다.
- 일반/코트 목록 모두 일시 → 코트/위치/사진 → 모집 인원/가격 순서로 정렬했다. 코트 신청은 입금 확인 후 확정된다는 구분을 유지했다.
- 알림과 활동 목록의 일정·위치 표시는 공통 아이콘으로 정리했다. 빈 목록에 남아 있던 ‘코트 없이 일반 매칭 개설 가능’ 문구는 현행 예약 코트 필수 정책에 맞췄다.
- 모든 변경은 UI 및 디자인 문서에 한정했다. 작업 시작 시점 해시와 비교해 서버·API·모집/금융 도메인, Claude 문서, 네이티브 소스가 보존됐음을 확인했다.
- 개발 전용 `/design-preview`에서 실제 목록 카드·신청 시트·입력 및 서비스 제공 항목 선택을 확인한다. 예시 데이터를 사용하고 저장/API 호출은 하지 않는다.
- `npm run lint`, `npm run typecheck`, `npm run build`, `git diff --check` 통과.
- `npm run test`: 59개 파일·410개 테스트 통과. 3개 파일·110개 DB 테스트는 실행 환경 조건으로 제외됐다.
- 375px에서 코트 카드·신청 시트·입력 상태를 확인했고, 320px 코트 카드·약관에 가로 넘침이 없었다. 신청 자기소개는 16px 글자·160px 높이·200자 제한이 유지된다. 공통 최소 높이는 CSS layer 안에 두어 각 textarea 높이를 덮어쓰지 않는다.
- 로그인하지 않은 `/my` 요청은 로그인으로 연결됐다. 보호된 운영/금융 화면의 모든 데이터 상태, 실계정 신청·수락·이체·환불 처리는 이번 디자인 검증에서 실행하지 않았다. 실제 iPhone 키보드·안전 영역·앱 복귀는 다음 실기기 검증 대상이다.
- 운영 배포·커밋·푸시·네이티브 재설치는 수행하지 않았다.
