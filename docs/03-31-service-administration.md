# 서비스 관리 · 문의 · 공지사항

## 확정 범위 (2026-10-13)

대표는 서비스 관리만 담당하고 코트 운영은 별도 운영자가 담당한다. 새 관리 시스템 대신 기존 앱의 마이 → 서비스 관리에서 문의·공지를 관리한다. 기존 내부 관리자 권한(INTERNAL_REVIEWER)만 사용한다. 일반 회원과 코트 운영자에게 관리 메뉴를 표시하지 않으며, 페이지·API 모두 현재 계정 상태와 권한을 확인한다.

로그인 문제 문의 주소는 사용자가 만든 `rallyon.support@gmail.com`이다. 로그인 화면에 주소와 메일 작성 링크를 표시한다. 로그인 후 이용 문의는 기존 1:1 문의로 접수한다. 이메일 자동 발송·메일함 연동·고정 응답 시간 약속은 추가하지 않는다. 메일함은 대표가 직접 확인한다.

## 문의 흐름

- 접수 → 관리자 알림 → 담당 맡기 → 회원 답변 → 필요하면 해결 완료.
- 서비스 관리에는 접수됨·검토 중 문의 수와 운영자 확인 중 문의 수를 구분한다. 기본 문의 목록은 답변할 문의이며 전체·상태별 조회를 제공한다.
- 새 문의는 활성 내부 관리자에게, 추가 문의·운영자 회신은 유효한 배정 담당자에게 알린다. 담당자가 없거나 비활성·권한 회수 상태면 활성 관리자에게 알린다. 본인 문의·본인이 개설한 매칭 문의는 본인이 처리하거나 처리 알림을 받지 않는다.
- 공개 답변·해결 완료는 회원에게, 운영자 대조 요청은 해당 코트 운영자에게 알린다. 운영자에게 회원 문의 원문·담당자의 공개 답변을 자동 노출하지 않는 기존 정책을 유지한다.
- 알림은 앱 내부 알림함에 기록하며 해당 문의로 직접 연결한다. 문의 원문·개인정보를 알림 본문에 복사하지 않는다. 매칭 소식 알림 설정과 관계없이 전달한다. 외부 푸시는 별도 작업이다.
- 문의 처리와 알림 저장은 같은 트랜잭션이며 같은 처리 요청을 재시도해도 중복 알림을 만들지 않는다.
- 기존 버전 충돌·본인 처리 금지·미해결 금전 건의 해결 완료 금지 규칙을 유지한다.

## 공지사항

- 관리자: 목록 → 새 공지 → 제목(120자)·본문(2,000자)·상단 고정 선택 → 미리보기 → 초안 저장 → 공개하기.
- 초안·공개·숨김을 구분하고 영구 삭제는 제공하지 않는다. 공개 공지를 수정해 저장하면 사용자에게 즉시 반영되므로 버튼에 이를 명시한다.
- 숨김은 사용자 목록에서 제외하며 다시 공개할 수 있다. 최초 공개 시각은 수정·재공개 시 유지한다.
- 사용자 목록: 공개 공지만, 상단 고정 우선·최초 공개 최신순. HTML을 실행하지 않고 일반 텍스트로 표시한다.
- 동시 편집은 버전으로 충돌을 차단한다. 새 초안은 요청 ID로 중복 생성을 방지한다. 작성·수정 담당자의 내부 ID와 시각을 보관한다.
- 기존 공지는 마이그레이션에서 공개 상태를 유지한다. 새 공지는 기본 초안이다. 기존 seed 스크립트는 개발·테스트용이며 운영 공지는 관리 화면에서 등록한다.

## 검증 기준

비로그인·일반 회원·권한 회수 계정의 관리 접근 차단, 문의 접수/답변/재문의/대조 알림과 중복 방지, 문의 직접 연결, 초안 비노출·공개·수정·고정·숨김·동시 편집 충돌을 검증한다. 모바일 320/375px에서 가로 넘침 없이 사용한다. 운영 DB 적용과 배포 여부는 작업 완료 보고에서 구분한다.

## 운영 반영 시 주의

운영 반영은 `docs/11-production-release.md`의 검증 후 승격 절차를 따른다. 이번 변경에는 `20261013100000_service_administration` 마이그레이션이 필요하다. 기존 공지 공개 상태와 내용은 보존한다.

이전 앱 버전은 공지의 초안·숨김 상태를 구분하지 않는다. 따라서 승격 전 공지 작성 검증은 반드시 분리된 테스트 DB에서 한다. 새 운영본 승격 전 운영 DB에 초안·숨김 공지를 만들지 않는다. 이 상태의 공지를 사용하기 시작한 뒤에는 상태 필터가 없는 이전 앱으로 단순 롤백하지 말고, 상태 필터를 포함한 수정본으로 복구해야 한다.
