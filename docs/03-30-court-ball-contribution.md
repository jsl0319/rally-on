# 참가자 공 준비 할인과 신청 가능 필터

2026-10-12 사용자 확정. 구현·로컬 검증 완료. 사용자 승인으로 운영 반영을 진행한다.

## 목적과 범위

참가자가 테니스공을 준비하는 실제 운영 방식을 참가비에 반영한다. 기존 신청·입금·환불 화면에 역할과 신청별 금액을 연결하며 새 결제 시스템이나 의존성은 추가하지 않는다. 외부에서만 할인 금액을 조율하는 대안은 입금 확인·환불 금액과 앱 표시가 달라지므로 사용하지 않는다.

## 확정 규칙

- 경기당 공 준비 참가자 1명. 공 준비로 **신청 접수가 성공한 순서**로 확보한다. 운영자 승인 대기도 자리를 확보한다. 동시 요청은 경기 잠금과 DB 유일성 제약으로 하나만 성공한다.
- 새 테니스공 1캔(최소 2구, 2026-10-12 후속 변경)을 가져와 함께 사용한다. 일반 참가비에서 5,000원 할인하며 일반 참가비는 반드시 5,000원 초과다. 운영자는 경기당 최대 5,000원의 할인 수입 감소를 고려해 일반 참가비를 직접 정한다.
- 철회·거절·만료·취소로 공 준비 자리가 해제된다. 기존 일반 참가자를 자동 전환하거나 신청 금액을 변경하지 않는다. 모집 및 성별 정원·입금 기한은 기존 정책을 따른다. 늦게 해제되어 새 신청을 받을 수 없으면 운영자가 기존 연락 수단으로 공 준비를 조율한다.
- 새 초안 생성·수정부터 적용한다. 기존 공개 경기와 신청 가격·공 제공 약속에는 소급하지 않는다. 과거 비공개 초안은 새 방식으로 저장한 뒤 공개한다.
- 신청 시 역할·납부액과 역할별 안내 동의를 고정한다. 일반/공 준비 선택을 바꾸면 동의를 다시 받는다. 이미 확보된 자리를 선택하면 충돌 안내 후 최신 상태를 다시 확인하며 일반 신청으로 자동 전환하지 않는다.
- 취소 시 할인 참가자는 할인된 실제 계약 참가비로 환불을 계산한다. 미확정 종료·전체 취소의 실제 입금 전액 반환, 초과 입금 반환, 기지급 차감은 유지한다.
- 공 미지참은 경기 시작 후 확정 참가자에 대해 운영자가 사실·사유를 확인해 한 번 기록한다. 최초 금액은 보존하고 5,000원 추가 납부를 별도 표시한다. 자동 송금이나 자동 벌금 부과는 하지 않는다. 기존 누적 수령 기록으로 추가 입금을 대조한다.
- 이미 환불을 지급·처리 중이거나 부분 반환을 합의한 신청은 미지참 추가 부과를 막고 먼저 당사자 확인을 안내한다. 소급해 반환 의무를 줄이지 않는다. 정정이 필요한 미지참 기록은 기존 문의로 처리하며 무조건 덮어쓰는 기능을 만들지 않는다.
- 추가 입금 미처리는 연락처 공개·거래 대조·원문 보존 판단에 반영한다.

## 표시

- 일반 매칭 카드: `남 1명 · 여 0명 남음`, 성별 무관이면 `성별 무관 2명 남음`. 참가비는 카드에서만 제거하고 상세에는 유지한다.
- `참여가능` 스위치: 모집 중, 시작 전, 남은 자리(남녀 정원 포함), 본인 개설 아님, 기존 신청 없음. 실력·추천 점수는 신청 제한으로 쓰지 않는다. 서버에서 재검증한다.
- 코트 상세의 `참가비 포함 항목` 독립 영역을 제거한다. 새 공 준비 정책은 가격 및 신청 역할 선택에서 보여 준다. 다른 제공 약속은 신청 안내와 기존 스냅샷으로 유지한다.
- 운영자 가격 입력: 일반/공 준비 금액을 함께 미리 보여 주고 할인 수입 감소를 안내한다. 운영자가 공을 제공하는 선택은 새 방식에서 받지 않는다.

## 검증 계획

동시 공 준비 신청 1건, 종료 후 재모집, 승인 방식별 역할 보존, 오래된 동의 거부, 할인액 입금 확정, 개인/전체 취소·초과 입금·부분 반환, 미지참 중복/권한/시작 전 차단과 추가 입금, 과거 거래 보존, 모바일 화면을 로컬 DB에서 확인한다. 운영 DB 변경·배포는 검증 후 별도 실행한다.

## 구현 및 검증 결과

- 일반 매칭 카드 성별 잔여 인원·참가비 제거, 서버와 상세의 신청 가능 판정 공통화, 참여가능 스위치와 정렬 유지 완료.
- 공 준비 자리의 경기 잠금·DB 부분 유일성, 신청별 가격 및 역할별 동의, 할인 입금 확정·취소 환불·부분 반환 상한·활동 화면 금액 연결 완료.
- 운영자 가격 입력과 할인 미리보기, 신청 역할 선택, 운영자별 납부액, 미지참 사유·중복 요청 보호·필수 앱 내 알림·추가 입금 대조 연결 완료. 추가 입금이 남으면 연락처 공개와 대조/보존 판단에서도 미해결로 유지한다.
- 과거 공개 슬롯은 할인 비활성 상태로 보존한다. 기존 신청의 금액·안내·환불·수령 이력을 갱신하는 SQL은 없다.
- 격리된 로컬 PostgreSQL에 추가형 마이그레이션 2개 적용. 단위/DB **540개 통과**. 린트·타입 검사·프로덕션 빌드 통과.
- 모바일 Playwright **20개 통과**: 참여가능 스위치·정렬 유지·성별 정원·비로그인·잘못된 필터, 320/375px 카드, 공 준비 신청→할인 입금→미지참→추가 입금, 기존 합의 반환 흐름. 화면 캡처 검토, 새 흐름 가로 넘침/실행 오류 없음.
- 이는 로컬 브라우저 검증이며 실기기 iPhone 검증·운영 DB 반영·커밋·푸시·배포는 아직 하지 않았다. 배포 시 DB 변경 후 앱을 배포해야 한다. 신버전 거래가 생긴 뒤 과거 앱으로 단순 롤백하면 할인 금액을 잘못 계산하므로, 롤백이 필요하면 해당 거래 쓰기를 먼저 중단하고 호환 버전을 사용한다.

## 운영 반영 및 테스트 데이터 교체 (2026-10-12)

- 사용자 요청으로 main 커밋·푸시 및 운영 배포를 진행한다. 추가형 마이그레이션 2개는 운영 빌드의 `prisma migrate deploy`로 적용한다. Claude의 푸시 알림 문서와 네이티브 앱 변경은 포함하지 않는다.
- `prisma/seed-discovery-demo.ts --date=2026-10-12 --expected-host=<운영 DB 호스트> --replace-existing --apply`로 일반 5개·코트 5개를 10월 13~15일에 생성한다. 날짜·성별 구성·플레이 목적·승인 방식·참가비를 분산한다. 코트 5개 모두 일반 참가비 10,000~22,000원과 공 준비 5,000원 할인을 사용한다. 실제 전화·송금·예약 대상이 아닌 가상의 시설과 계정이다.
- 교체 대상은 저장소 시드의 고정 ID·이전 배치와 일치하는 매칭에 한정한다. 신청·채팅·문의·거래 인계·공급 문제 기록이 연결된 매칭은 삭제하지 않는다. 실제 계정의 직접 등록 매칭은 손대지 않는다. 남아 있는 합성 계정·시설의 개인정보나 거래 이력을 일괄 삭제하지 않는다.
- 삭제와 새 생성은 한 DB 트랜잭션이며 기본 실행은 읽기 전용 미리보기다. 같은 배치 재실행은 중복 생성하지 않는다. 로컬 PostgreSQL에서 생성 10개, 이력 없는 기존 매칭만 삭제, 신청 연결 건 보존, 재실행 무변경을 확인했다.
- 생산 환경 배포·데이터 적용 결과는 작업 완료 보고에서 실제 확인한 상태를 기준으로 안내한다.

## 목록·상세 가독성 후속 변경

- 일반 매칭 카드의 추천 이유 문장을 제거한다. 추천 계산과 상세 설명은 유지한다.
- 코트 목록의 승인 방식 배지를 제거한다. 상세와 신청 확인에서는 “신청 후 바로 입금 안내” 또는 “운영자가 수락하면 입금 안내”로 결과를 설명하고, 두 방식 모두 실제 입금 확인 후 확정됨을 명시한다.
- 1인 참가비·공 준비 5,000원 할인·선착순 1명을 가격과 함께 강조한다. 할인 자리가 이미 확보됐거나 신청이 마감되면 모집 완료/마감으로 표시한다.
- 날짜·게임 유형 필터와 별도 시간 빠른순/낮은 가격순 정렬을 코트 목록에도 제공한다. 가격 정렬은 할인 전 1인 금액 기준이며, 날짜는 한국 시간 기준이다. 필터·정렬을 서버 조회 제한 50건보다 먼저 적용한다. 빈 결과·초기화·오류·재시도를 제공한다.
- 상세는 일시·자리·금액 → 소개·위치 → 신청/입금·취소/환불 순으로 배치한다. 신청 후에는 내 신청 상태와 필요한 입금·환불 행동을 우선한다. 마지막 확인 시각은 하단으로 옮기되, 갱신 실패와 진행 불명확 경고는 숨기지 않는다.
- 새 신청의 공 조건은 최소 2구로 변경하고 안내 버전을 v5로 갱신한다. 오래된 화면의 해시는 재확인을 요구한다. 기존 v4 신청의 원문·최소 3구 계약은 덮어쓰지 않으며 신청 후 준비 안내도 저장된 조건을 따른다.
- 반복되는 일정·가격 설명과 항상 보이던 새로고침 버튼을 줄인다. 할인 미지참 추가 입금, 확정 전/후 환불 기준, 최소 구성 미달 취소 등 의사결정에 필요한 내용은 남기고 상세 규칙은 펼쳐 볼 수 있게 한다. 새로운 승인·취소·금액 정책이나 DB 마이그레이션은 추가하지 않는다.
- 후속 검증: 단위·격리 DB 546개, 모바일 E2E 23개, 린트·타입 검사·프로덕션 빌드 통과. 320/375px 목록, 날짜·유형·가격 정렬과 빈 결과 복구, 공 준비 자리 확보 후 모집 완료 표시, 신청 조건 변경 시 재동의, 할인 입금·미지참 추가 입금 흐름을 확인했다. 이 후속 UX 변경은 아직 커밋·푸시·운영 배포 전이며 실제 iPhone에서는 별도 확인이 필요하다.

### Mobbin 참고 후 시각 정리

- 해결할 문제: 할인 금액을 큰 색상 박스로 반복해 보여주면 행사 배너처럼 느껴지고, 일정과 가격의 중요도가 흐려진다. 신청 전 필요한 정보를 읽는 핵심 흐름의 시각 정리만 진행한다. 새 기능·요금·승인 정책은 추가하지 않는다.
- [ClassPass 클래스 상세](https://mobbin.com/screens/fa71be76-bf15-43b3-af2f-e31d84bd6b22): 사진 아래 제목·장소·일정을 차례로 읽고, 가격과 예약 버튼은 하단에 유지하는 구성을 참고한다. 코트 상세의 시선 흐름과 고정 신청 영역에 적용한다.
- [IKEA 가격 표시](https://mobbin.com/screens/1bb148a9-7abe-4a84-83b6-6fd610ebc781): 작은 자격 설명과 가격 크기 차이로 혜택을 구분하는 방법을 참고한다. 공 준비 혜택은 채운 배너 대신 1인 금액과 정렬한 텍스트로 표시하며, 기본 참가비와 조건부 할인 금액을 혼동하지 않게 한다.
- [Viator 위치·예약 영역](https://mobbin.com/screens/8279137c-58e2-4d0e-9683-b54f3a5d5493): 위치 정보와 주된 예약 행동을 분리하는 구성을 참고한다. 길찾기는 보조 버튼으로 낮추고 신청 버튼은 주된 행동으로 유지한다.
- 목록의 할인 배경·장식 아이콘을 제거한다. 상세는 왼쪽 정렬한 일정, 짧은 모집 현황, 1인/공 준비 금액 순으로 배치한다. 선착순 1명·최소 2구·미지참 추가 입금·취소환불 기준과 신청 후 금융 정보는 보존한다. 기존 컴포넌트와 스타일만 수정하는 것이 더 단순하므로 신규 디자인 라이브러리나 이미지 제작은 사용하지 않는다.
- 시각 정리 후 린트·타입 검사·프로덕션 빌드, 단위·DB 546개와 모바일 E2E 23개를 다시 통과했다. 320/375px에서 가로 넘침 없이 표시되고, 스크롤 시 제목과 신청 영역이 유지된다. 화면 캡처로 목록·상세·신청창을 확인했다. 실제 iPhone 검증과 운영 배포는 아직 진행하지 않았다.

### 목록 공통 혜택 안내 (2026-10-14, 카드 상태 배지 제거로 최종 수정)

- 사용자 문제: 모든 카드에 `공 준비 · 선착순 1명 / 5,000원 할인`을 반복해 목록이 복잡해지고 카드 높이가 늘어난다. 공통 정책은 목록에서 한 번 안내하고, 경기별 공 준비 가능 여부는 상세에서 확인하도록 바꾼다. 할인·선착순 확보·미지참·환불 정책과 API는 변경하지 않는다.
- Mobbin 근거: [Booking.com 목록 상단 혜택 안내](https://mobbin.com/screens/e8b417ce-4f0a-4bfe-887c-47eb4ec9b208)의 공통 정보와 개별 상품 카드 분리를 참고했다. 큰 프로모션 대신 작은 공통 안내 영역으로 표시한다. [Apple Fitness 운동 선택 목록](https://mobbin.com/screens/87a2df92-c761-472e-8e91-37803295ee1f)의 짧은 텍스트 묶음과 조밀한 행 구성을 카드 하단에 적용한다.
- 필터 아래, 첫 카드 앞에 `공 준비하면 5,000원 할인`과 `경기당 선착순 1명 · 새 공 1캔, 최소 2구`를 한 번 표시한다. 해당 결과에 할인 적용 경기가 있을 때만 노출하며 로딩·오류·빈 결과에서는 표시하지 않는다. 펼치면 역할 선택·신청 접수 순 확보·미지참 추가 입금 방법을 확인할 수 있다.
- 카드의 할인 금액·선착순 설명 행과 `공 준비 가능 / 공 준비 마감` 배지를 모두 제거한다. 카드 하단은 왼쪽의 남은 인원 또는 모집 상태와 오른쪽의 1인 참가비만 유지한다.
- 상단 공통 안내를 펼치면 경기 상세에서 공 준비 자리를 확인하도록 안내한다. 상세의 실제 할인 참가비·자리 상태와 신청 시 조건·동의 흐름은 그대로 유지한다.
- 개발용 `/design-preview`의 코트 매칭 탭에서도 실제 공통 안내·카드 컴포넌트로 가능·공 준비 마감·할인 없음·모집 마감 예시를 비교할 수 있게 한다. 운영 DB의 테스트 배치나 기존 사용자의 신청·입금은 수정하지 않는다.
- 검증: 린트·타입 검사·단위 442개·프로덕션 빌드 통과. DB 의존 테스트 132개는 기본 검사에서 제외됐으며, 별도 임시 PostgreSQL에서 관련 모바일 E2E 2개를 통과했다. 320/375px 가로 넘침, 공통 안내 한 번 노출·펼치기·빈 결과 숨김, 신청 후 공 준비 마감 표시와 기존 입금 처리 흐름을 확인했다. 실제 iPhone 확인과 운영 배포는 아직 진행하지 않았다.
- 개발 검증 참고: 기존 `favicon.ico`를 기본 개발 서버(Turbopack)가 읽지 못하는 오류가 있어 운영 빌드와 같은 Webpack 방식으로 미리보기와 E2E를 실행했다. 확정된 아이콘 파일은 변경하지 않았다.
- 검토 이력: [TheFork 예약 카드의 작은 혜택 배지](https://mobbin.com/screens/0a4043a9-cf05-4172-9110-ad0dae6cbf20)를 참고해 가능·마감 배지의 대비를 높인 시안을 검증했으나, 사용자의 최종 요청에 따라 카드 상태 배지 자체를 제거했다. 해당 배지 시안은 현재 화면에 적용하지 않는다.
- 배지 제거 후 검증: 린트·타입 검사·단위 442개·프로덕션 빌드 통과(DB 의존 132개 제외). 320/375px 미리보기에서 카드 6개 모두 공 준비 표시가 없고 가로 넘침이 없음을 확인했다. 공통 안내 펼치기에서 상세 확인 안내와 미지참 조건을 확인했으며, 기존 E2E의 기대 결과를 배지 없음으로 수정했다. 이번 시각 변경에서 DB/E2E 재실행·운영 배포·실제 iPhone 확인은 진행하지 않았다.
- 공통 안내 가시성: [Grab 예약 목록의 대비가 뚜렷한 혜택 안내](https://mobbin.com/screens/febd145a-0377-4bfb-82e6-028d2d1b7b5a)를 참고해 진한 브랜드 녹색 배경에 흰색 15px 굵은 제목과 테니스공 색의 `5,000원 할인`을 표시한다. 조건은 12px 밝은 글자로 읽을 수 있게 하며, 공통 안내의 위치·펼치기·노출 조건을 유지한다.
- 목록 상단 보조 링크: 매칭의 `내 매칭`과 코트 매칭의 `내 신청 내역`은 같은 흰색 배경·진한 녹색 글자·얇은 테두리로 통일한다. 보이는 높이는 44px에서 32px로 줄이고 세로 터치 영역은 44px를 유지한다. 각각 기존 `/activity/received`, `/activity/sent`로 이동하며 다른 화면의 보조 버튼 크기는 변경하지 않는다.
- 안내·상단 버튼 검증: 린트·타입 검사·단위 442개·프로덕션 빌드 통과(DB 의존 132개 제외). 320/375px에서 양쪽 버튼이 같은 색상·32px 높이이고 공통 안내는 접힌 상태에서 64px로 유지됨을 확인했다. 가로 넘침 없이 조건 펼치기·접기가 동작한다. 이번 변경은 UI만 수정했으며 DB/E2E 재실행·운영 배포·실제 iPhone 확인은 하지 않았다.
