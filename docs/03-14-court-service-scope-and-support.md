# 코트 매칭 제공 범위·책임·문의 운영 정리

2026-10-01 검토 · 2026-10-03 갱신 · R06 후속 · 검토 기준 `2dfc261` · **제공 범위 구현·운영 반영 완료**

2026-10-03 사용자 승인으로 제공 범위와 신청 후 전화 문의를 함께 운영에 반영했다. 기능 커밋은 `90a8b5c`이며, DB 적용·배포 확인은 [03-15](03-15-court-operator-contact.md)의 운영 반영 기록을 따른다. 아래 §9의 미배포 표시는 당시 로컬 검증 종료 시점의 기록이다.

같은 날 후속 시안을 사용자 피드백에 따라 [03-16](03-16-court-provider-information-design.md)의 기본정보 재사용·문의 연락처 중심으로 수정했다. 별도 공개 사업자 정보 입력·재심사와 기존 경기의 새 신청 중지는 이번 안에서 제외했다. 기존 코트에 연락처를 한 번 저장해 재사용하는 구조를 유지하고, 사용자 승인으로 최초 설정·매칭 등록 동선을 실제 화면에 연결했다. 로컬 구현·검증을 마쳤으며 운영 반영 전 상태다.

## 1. 이번 작업의 목적과 경계

참가자가 돈을 보내기 전에 **누가 무엇을 제공하며 문제가 생기면 어디로 연락하는지** 알 수 있게 한다. 신청·입금·취소 기능이 있어도 공이나 현장 진행자가 있는지, 시설을 쓸 수 없을 때 누가 답하는지 모르면 실제 이용을 마무리할 수 없다.

현재 코트 매칭 정본은 [03-2](03-2-court-match-operator-hosted-redesign.md)다. 신청 전 안내·확인 기록은 [03-12](03-12-court-application-notice.md), 취소 조건 변경 시 재확인은 [03-13](03-13-court-cancellation-reconfirmation.md)에서 구현했다. 이 문서는 남은 제공 범위와 운영 사실을 정리하며 기존 환불율·모집 기한을 다시 정하지 않는다.

새 고객센터나 PG 대신 기존 운영자 등록·코트 상세·신청 안내·1:1 문의를 보완하는 방향이다. 확정된 제공 범위의 등록·안내를 구현하고 전용 로컬 DB로 검증했다. 공개 제공자 정보·실제 문의 채널은 별도 단위로 남긴다. 운영 DB·배포·운영자 권한·크론은 변경하지 않았다. 클로드의 기존 작업도 유지한다.

## 3. 확정한 운영 사실과 남은 결정

2026-10-01 사용자 답변: **코트 이용·매칭 참가만 기본 포함하고 공·장비·레슨·현장 진행은 경기별로 명시한다. Rally On은 현재 개인 운영이며 사용자가 유일한 문의 담당자다. 문의 이메일/채널과 응대 시간은 미정이다.** 아래 선택지는 결정 근거로 보존하며 첫 번째 안을 구현한다.

### A. 기본 참가비의 포함 범위

| 선택지 | 사용자 경험 | 구현·운영 영향 |
| --- | --- | --- |
| 코트 이용·매칭 참가만 기본 포함, 나머지는 경기별 명시 — 권장 | 레슨·공·진행자 제공을 자동으로 기대하지 않음. 경기마다 준비물을 알 수 있음 | 기본 범위는 공통 안내, 공·장비·레슨·진행은 선택 항목. 기존 경기에 기본값 소급 적용 금지 |
| 테니스공까지 기본 포함 | 개인 공을 준비할 필요가 없는 상품으로 이해 | 모든 운영자가 공 제공을 실제 보장해야 함. 미제공 처리도 정해야 함 |
| 모든 항목을 경기별 선택 | 상품 차이를 가장 정확히 알 수 있음 | 운영자의 입력·확인 부담 증가. 필수 선택 누락 시 새 공개를 막는 검증 필요 |

범위 답변 후에도 다음은 구분한다: 레슨과 단순 경기 진행, 공 제공과 개인 장비 대여, 코트 이용 시간과 개인 플레이 시간, 포함 비용과 주차·대여 등의 추가 비용. 정하지 않은 내용을 `포함` 또는 `미포함`으로 임의 저장하지 않는다.

더 단순한 대안은 기존 이용 안내에 수기로 적는 것이다. 다만 빈 안내를 허용하면 같은 누락이 반복되므로 첫 구현은 짧은 선택 항목과 선택한 내용의 안내 기록을 권장한다. 새 상품·결제 방식 추가는 필요하지 않다.

### B. Rally On 운영 주체와 문의 창구

개인 운영·사용자 1인 문의 담당은 확정했다. 실제 공개 가능한 문의 채널과 응대 시간은 미정이다. 미정인 연락처·처리 기한을 추정하거나 테스트 값을 실제 화면에 넣지 않는다. 개인 운영이라는 답변만으로 사업자 해당 여부나 법적 의무 면제를 결론내리지 않는다.

그 답변을 바탕으로 후속 확인할 정보는 다음과 같다.

- 서비스 운영자와 각 코트 서비스 제공자의 표시 정보. 양자가 같다고 가정하지 않음.
- 현장 이용 안내 담당자와 연락 방법. 플랫폼 문의 이메일이 있다고 현장 대응이 되는 것은 아님.
- 일반 문의의 첫 답변 목표, 경기 임박·당일 연락 방법, 부재 시 대체 담당. 아직 `24시간`, `당일 처리` 등의 수치를 약속하지 않음.
- 영수증 발급 주체·방법, 제공 계약, 사고 대응·보험, 개인정보 책임자와 보관·파기 기준은 별도 확인.

코트 운영자와 Rally On 운영자가 같은 한 사람인 시험 운영도 가능한 운영 사실이지만, 실제로 독립적인 문의 검토가 가능한지 확인해야 한다. 현재 서버는 내부 담당자가 **본인 또는 본인이 주최한 경기의 문의를 처리하는 것**을 막는다. 이 제한을 제거하는 대신 대체 담당자 확보를 먼저 검토한다.

## 4. 문서 충돌과 수정안

아래는 검토용 문구이며 아직 이용약관·정본에 적용하지 않았다.

### 4.1 서비스의 역할과 문의

현재 약관은 분쟁 중재를 부인하지만 기존 문의 기능은 담당자가 원인을 확인하고 운영자 대조 요청·답변·처리 결과를 기록한다. 법적 중재나 배상 보증을 약속하지 않으면서 실제 수행하는 업무를 설명하는 안을 권장한다.

수정안:

> Rally On은 매칭 정보 제공, 참가 신청·승인과 입금·환불 처리 기록을 돕습니다. 이용 중 문제가 생기면 담당자가 1:1 문의를 확인하고, 필요한 내용을 코트 운영자와 대조해 답변과 처리 결과를 안내합니다. 실제 입금·환불 이체는 코트 운영자 또는 거래를 인계받은 담당자가 진행합니다.

일반 매칭 약관의 “채팅에서 코트를 정한다”는 설명도 새 일반 매칭의 사전 코트 확보 정책과 맞지 않는다. 코트 매칭에 일반 매칭의 비용 분담 규칙을 적용하지 않도록 다음처럼 구분하는 안을 권장한다.

> 일반 매칭은 모집자가 이미 예약한 외부 코트와 일정을 등록해 참가자를 모집합니다. 참가비 정산은 모집자와 참가자가 직접 진행합니다. 코트 매칭은 코트 운영자가 공개한 시간과 조건에 따라 참가하며, 신청 전에 표시된 참가비와 입금·취소 안내를 확인합니다.

### 4.2 시설·현장 안전과 사고

`03-2` §3.7(b)와 현재 약관의 “개인 부상·소지품은 각자”는 이미 확정된 운영 분담 표현이지만, 사고 원인과 무관한 책임 면제로 확장될 수 있다. 시설·현장 관리 담당은 유지하고 개별 손해 책임을 일괄 단정하지 않는 안을 권장한다. 배상 기준이나 보험 보장을 새로 만드는 변경은 아니다.

수정안:

> 코트 운영자는 시설 이용과 현장 안전을 안내합니다. 참가자는 이용 수칙을 지키고 위험한 상황에서는 플레이를 중단해 현장 담당자에게 알려 주세요. 시설 문제나 사고에 관한 문의는 사실관계를 확인해 처리하며, 책임과 보상은 사고 원인과 관련 법령에 따라 판단합니다. 이 안내는 법령상 책임을 면제하거나 이용자의 권리를 제한하지 않습니다.

실제 현장 연락 방법이 확보되지 않은 상태에서 “현장 담당자에게 연락” 문구만 추가하고 완료로 처리하지 않는다. 경기 진행자 상주 여부도 별도 표시가 필요하다.

### 4.3 공개 제공자 정보와 비공개 심사 자료

`03-1`의 유지 대상인 운영자 심사·정보 보호 절은 대표자·연락처·증빙의 비공개를 전제로 한다. 신청 전 제공자 표시를 위해 기존 심사 자료를 공개로 전환하는 대신 **확인된 공개 사업자 정보와 고객용 연락 경로를 별도 관리**하는 안을 권장한다.

이용자가 보는 이름·주소·연락 방법과 내부 심사 증빙의 목적을 분리하면 기존 개인정보 경계를 유지할 수 있다. 실제 필요한 법정 표시 항목과 공개 범위는 운영 주체·계약 역할 확인 후 정한다. 단순히 닉네임에 `운영자`를 붙이는 대안은 실제 제공자 확인 문제를 해결하지 못한다.

## 6. 전체 구현 순서와 완료 조건

1. **제공 범위 확정:** 정본 `03-2`에 사용자가 고른 범위만 기록한다. 운영자 초안 등록의 선택 항목 → 서버 입력 검증 → 코트 상세·신청 안내에 같은 내용을 연결한다. 가격·레슨 제공 등의 새 약속을 임의로 추가하지 않는다.
2. **기록 보존:** 확인한 포함 범위와 제공자 표시 정보를 신청 안내 스냅샷·버전·해시에 포함한다. 기존 신청의 안내를 덮어쓰거나 과거 확인을 만들지 않는다. 기존 공개 경기도 새 기본값으로 자동 변경하지 않는다. 누락 항목의 기존 경기 처리 방식은 데이터 변경 전에 결정한다.
3. **실제 연락 경로:** 확인된 플랫폼 문의 채널은 로그인 불가 화면에서도 접근하게 하고, 코트 현장 연락 방법은 확인된 공개 범위에서 제공한다. 새 외부 서비스나 고객센터 도입 없이 실제 사용하는 채널부터 연결한다.
4. **약관·개인정보 일치:** §4의 초안을 실제 운영 사실과 법률 검토에 맞춰 반영한다. 신청 안내에서 확인한 내용과 모순되지 않게 한다. 사업자 신원, 환불율 적합성, 보관 기간은 코드 테스트로 검증했다고 표현하지 않는다.
5. **검증:** 새/기존 경기와 신청 이력, 필수 항목 누락, 변경된 안내 재확인, 다른 운영자 수정 거절, 비공개 심사 자료 비노출, 로그인 불가 문의 경로, 모바일 가독성을 확인한다. 코드를 바꾼 단위별로 린트·타입·관련 테스트·빌드를 실행한다. 운영 DB에 테스트를 넣지 않는다.

이번 구현은 아래 §8의 제공 범위에 한정한다. 1번과 2번 중 포함 범위의 기록 보존을 완료했다. 공개 제공자 정보는 아직 기록 대상에 추가하지 않았고, 실제 연락 경로와 약관·개인정보 정비도 미완료다. 운영상 답변이 없는 항목은 보류 상태로 명시하고 관련 구현을 완료로 표시하지 않는다.

## 7. 법령 확인과 판단의 한계

2026-10-01 국가법령정보센터 원문을 다시 확인했다.

Rally On의 구체적인 법적 지위와 필요한 고지 항목, 현재 100/50/0 환불율의 적합성은 실제 계약·상품 범위 확인 후 자격 있는 전문가와 검토할 사안이다. 위 두 조문 확인만으로 서비스 전체의 법적 적합성이나 사고 책임을 확정하지 않는다.


## 8. 확정된 제공 범위의 구현

- `CourtSlot.serviceScope`는 공(`balls`)·장비 대여(`equipment`)·레슨(`lesson`)·현장 경기 진행(`facilitator`)의 포함 여부를 저장하는 nullable JSON이다. 네 boolean을 모두 명시하며 자동 선택·기본값은 없다. `true`는 표시된 참가비에 포함, `false`는 미포함이다. 미포함을 유료 추가 구매나 현장 대여 가능으로 해석하지 않는다.
- 운영자는 초안 생성·수정 때 네 항목을 선택한다. 클라이언트와 서버가 누락·잘못된 타입을 거절한다. 기존 미완성 초안도 포함 여부를 정하기 전에는 최초 공개할 수 없다(`COURT_SERVICE_SCOPE_REQUIRED`). 공개된 Slot 수정 금지는 유지한다.
- 기존 공개 경기는 NULL 그대로 보존한다. 상세와 새로운 신청 안내에서는 추가 제공 정보 미등록을 표시하며 현재 신청 권한·기존 조건을 임의로 바꾸지 않는다. 기본 포함 문구도 새 제공 범위가 있는 경기에서만 표시한다. 과거 안내에는 새 항목을 만들어 넣지 않는다.
- 상세·운영자 카드·신청 안내에서 포함 범위를 확인한다. 안내 버전 `court-application-2026-10-01-v2`는 구조화된 값과 실제 안내 문구를 모두 저장하고 해시에 반영한다. 조건 변경 시 기존 재확인 절차를 따른다. v1 기록은 그대로 읽는다.
- 마이그레이션 `20261001010000_court_service_scope`는 nullable 열 하나만 추가하고 과거 Slot·신청 데이터를 갱신하지 않는다. 운영 반영 시 API·화면을 함께 반영하고 기존 운영 DB 연결로 새 코드를 먼저 실행하지 않는다. UI/API 변경 이후 오래된 등록 화면의 저장 요청은 새 필수 항목 때문에 422가 될 수 있으므로 새로고침이 필요하다.
- 실제 문의 채널·응대 시간·공개 제공자 정보·법률 검토·개인정보 보관 및 파기는 미완료다. §4 약관 문구는 검토안으로 유지하고 이번에 공개 약관을 바꾸지 않는다. 사전 문의의 경기 연결은 후속 후보였으나 §10 사용자 방향에 따라 구현 대상에서 제외했다.

## 9. 검증 결과와 다음 작업 (2026-10-02)

- `npm run check` 통과: 린트, 타입 검사, 56개 파일의 414개 테스트(단위 336개·실제 DB 78개), 프로덕션 빌드. 마지막 입력 오류 표시 수정 후 린트·타입 검사·빌드도 다시 통과했다. Prisma 스키마 검증·Client 생성 및 전용 로컬 DB의 마이그레이션 적용을 확인했다.
- 모바일 E2E 7개 통과: `court-application-notice`, `court-composition`, `court-cancellation`. 새 제공 범위의 무선택 상태·필수 검증·저장·다시 열기·공개·상세·신청·과거 안내 보존을 확인했다. 항목을 선택하면 이전 누락 오류가 사라진다. 변경한 모바일 화면의 사진을 직접 확인했고, 브라우저 실행 오류와 가로 넘침도 검사했다.
- 실제 DB 검증에서는 다른 운영자 수정 거절, 공개 후 수정 금지, 미등록 초안 공개 차단, 안내 변경 재확인, 저장한 신청 안내의 불변성을 확인했다. 기존 공개 경기의 NULL과 v1 신청 기록은 보존했다.
- 모든 DB 검증은 전용 로컬 DB를 사용했다. 운영 DB 마이그레이션·배포·커밋·푸시는 이번 단위에서 실행하지 않았다. 운영 반영 때에는 §8의 nullable 열 추가를 먼저 적용한 뒤 대응 코드가 배포되도록 한다.

신청 후 운영자 연락 방식은 §10과 03-15로 진행했다. 남은 단위는 §3의 Rally On 문의 운영 사실과 공개 제공자 정보 확인이다. 신청 전 문의 연결은 진행하지 않는다. 문의 채널·응대 시간·현장 연락·대체 담당자는 실제 운영 가능한 답변을 받은 뒤 안내에 반영한다. 약관·공개 제공자 정보·보관 정책 검토까지 완료됐다고 표시하지 않는다. 크론 보류는 유지한다.

## 10. 신청 전 판단과 신청 후 운영자 연락 — 확정 (2026-10-02)

사용자는 코트 매칭 상세 정보로 신청 여부를 결정하며 사전 담당자 문의 연결은 불필요하다고 결정했다. 신청 후 운영자 업무용 전화 문의와 참가 확정 후 기존 Match 단체 채팅을 사용한다.

- 신청 접수 후 종료 24시간까지 본인 신청자에게 전화번호를 공개한다. 철회·거절·만료·취소 뒤에는 미처리 입금·환불이 있는 동안만 공개하고, 종료 24시간이 지나도 미처리 거래는 해결까지 유지한다.
- 새 코트 매칭 공개부터 업무용 전화번호·연락 가능 시간 등록을 필수로 한다. 기존 공개 경기는 유지하며 임의 번호를 채우지 않는다.
- 운영자가 번호를 직접 등록하고 공개 범위를 확인한다. 외부 시설 대표번호와 매칭 담당자의 번호가 같다고 추정하지 않는다. 번호 변경은 현재 연락처에 반영하고 공개 중단·비활성화 때에는 숨긴다.
- 연락 두절·환불 미처리·앱 문제는 기존 Rally On 문의 경로를 유지한다. 탈퇴 참가자의 남은 거래는 기존 제한 거래 화면에서 같은 기준으로 연락할 수 있다.

구현·검증·정확한 API 공개 기준은 [03-15](03-15-court-operator-contact.md)를 따른다. 정본의 문의 단일화·연락처 비노출 정책, API·ERD·개인정보 안내와 일반 Match/운영자 주최 Match의 채팅 문서 차이도 이 확정안에 맞춰 갱신한다. 별도 1:1 채팅·외부 유료 서비스·크론 변경은 추가하지 않는다. 플랫폼의 외부 문의 채널·응대 시간과 약관의 책임 문구·법률 검토는 이 작업으로 완료됐다고 표시하지 않는다.
