# M9 제한된 사용자 테스트 운영 가이드

## 1. 목적과 범위

M9은 기능 수를 늘리는 단계가 아니라 Core MVP의 핵심 가설을 실제 사용자에게 검증하는 단계다.

> 테니스 초보자가 상대방의 수준과 매칭 조건을 이해하면, 처음 보는 사람에게 같이 치기를 신청하는가?

테스트는 5~10명의 테니스 입문자를 대상으로 1~2주 동안 진행한다. 코트 운영자 기능, 앱 결제, 실시간 채팅, 후기·랭킹·커뮤니티 기능은 포함하지 않는다.

## 2. 테스트 시작 전 필수 확인

다음 항목이 모두 준비되기 전에는 참여자를 실제 매칭에 초대하지 않는다.

- [ ] 운영 문의 채널을 확정했다. 수락 후 참가 취소, 상대방 불편 신고, 코트 정보 오류는 이 채널로 접수한다.
- [ ] 테스트 운영자와 모집자가 코트 예약·비용·환불 책임이 서비스 밖에 있음을 이해했다.
- [ ] 참여자에게 비공개 MVP임, 앱 결제가 없다는 점, 서비스 내 Match 채팅의 입장 범위를 안내했다.
- [ ] 실제 사용자 데이터가 들어간 화면을 외부에 공유하거나 녹화하지 않는 원칙을 정했다.
- [ ] 운영자는 `/terms`, `/privacy`에 남아 있는 정식 공개 전 확정 항목을 인지했다.
- [ ] 운영자는 장애 시 매칭을 중단하고 안내할 방법을 준비했다.

2026-10-13 문의 채널 확정: 로그인 문제는 `rallyon.support@gmail.com`, 로그인 후 서비스 이용 문의는 앱 내 1:1 문의로 접수한다. 대표가 직접 확인하며 고정 응답 시간은 아직 정하지 않았다. 최신 문의 운영 정책은 `docs/03-31-service-administration.md`를 따른다. 개인정보 보관 정책은 관련 최신 정책 문서를 따른다.

## 3. 참여자 모집 기준

### 권장 대상

- 테니스를 시작한 지 약 0~3년이고, 레슨 또는 기초 랠리 경험이 있는 사람
- 고정 테니스 메이트가 부족하거나 처음 보는 사람과 가볍게 연습할 의향이 있는 사람
- 카카오 로그인과 모바일 웹 사용이 가능한 사람

### 제외 또는 보류

- 앱 내 결제, 코트 예약 보장, 실시간 채팅을 기대하는 사람
- 수락 후 참가 취소·신고·차단의 정식 기능이 반드시 필요한 상황인 사람
- 운영 문의 채널에 동의하지 않거나, 실명·연락처를 서비스에 직접 입력하려는 사람

성별·연령은 이 테스트의 선별 또는 분석 항목으로 수집하지 않는다.

## 4. 참여자 안내문 초안

테스트 시작 전에 아래 내용을 그대로 또는 같은 의미로 안내한다.

> Rally On은 테니스 초보자가 함께 칠 사람을 찾고 약속을 조율하도록 돕는 비공개 MVP예요. 코트 예약과 비용 정산은 참여자끼리 직접 진행하며, Rally On에서 결제하거나 예약을 보증하지 않아요. 서비스 내 Match 채팅은 모집자와 수락된 참가자에게만 보여요. 수락 후 참가 취소, 코트 정보 오류 또는 상대방 관련 문제는 앱 기능이 아니라 테스트 운영 문의 채널로 알려 주세요.

참여자에게 전화번호, 이메일, 외부 예약 번호 또는 예약 확인서를 앱에 입력하지 말라고 다시 안내한다.

## 5. 운영 시나리오

한 번의 테스트에는 최소 모집자 1명과 참가자 1명을 배정한다. 가능한 경우 참여자 역할을 바꿔 한 번씩 경험하게 한다.

### A. 참가자 흐름

1. 카카오 로그인 후 닉네임 확인과 테니스 프로필 온보딩을 완료한다.
2. 홈의 추천 또는 전체 매칭에서 후보를 찾는다.
3. 매칭 상세에서 일정, 지역, 코트 상태, 비용, 모집 조건을 확인한다.
4. 같이 치기 신청을 보내고 활동 화면에서 상태를 확인한다.
5. 수락되면 서비스 내 채팅방과 다음 행동을 확인한다.

### B. 모집자 흐름

1. 실제로 예약한 외부 코트의 이름·주소·이용 시간·전체 비용을 입력해 Match를 등록한다. 코트를 확보하지 못한 경우에는 일반 매칭을 만들지 않고 `코트 매칭`에서 운영자가 공개한 시간을 확인한다.
2. 신청자의 당시 테니스 프로필과 짧은 메시지를 확인한다.
3. 수락 또는 거절 후 참가자 화면의 상태 변화를 확인한다.
4. 매칭이 진행되면 모집 마감과 일정 종료 뒤 완료 처리를 확인한다.

`COURT_TBD`는 새 테스트 시나리오로 만들거나 참가자를 모집하지 않는다. 이미 존재하는 기록을 점검해야 하면 기존 모집자·기존 수락 참가자만 상세, 채팅, 완료 처리를 계속할 수 있는지만 운영자가 확인한다. 공개 목록·추천·새 신청 화면에서는 이 기록이 보이지 않아야 한다.

## 6. 퍼널 기록 양식

운영자는 참여자 식별 정보를 기록하지 않고 임의의 `P01` 같은 테스트 코드만 사용한다. 한 행은 한 참여자·한 세션이다.

| 테스트 코드 | 역할 | 온보딩 완료 | 상세 확인 | 신청 시도 | 신청 완료 | 수락/거절 확인 | 완료 처리 확인 | 막힌 단계·짧은 이유 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| P01 | 참가자 | 예/아니오 | 예/아니오 | 예/아니오 | 예/아니오 | 예/아니오 | 해당 없음 |  
| P02 | 모집자 | 예/아니오 | 해당 없음 | 해당 없음 | 해당 없음 | 예/아니오 | 예/아니오 |  

기록에는 닉네임, 신청 메시지 원문, 코트 주소 전문, 채팅 메시지 원문을 넣지 않는다.

## 7. 짧은 인터뷰 질문

신청하지 않았거나 중간에 멈춘 경우에만 5분 이내로 묻는다.

1. 이 매칭에 신청해도 괜찮겠다고 느낀 정보와 부족했던 정보는 무엇인가요?
2. 코트 상태와 비용 안내를 어떻게 이해했나요?
3. 신청 또는 수락 뒤 다음에 무엇을 해야 하는지 알기 쉬웠나요?
4. 처음 보는 사람과 치는 데 가장 부담스러웠던 점은 무엇인가요?
5. 다시 사용한다면 꼭 바뀌었으면 하는 한 가지는 무엇인가요?

인터뷰 메모는 사실과 요약만 적고, 참여자가 말한 연락처·민감한 개인 사정·채팅 내용은 적지 않는다.

## 8. 운영 중단과 즉시 대응 기준

다음 상황은 기능 개선보다 참여자 안전과 데이터 보호를 우선한다.

| 상황 | 즉시 조치 | 이후 기록 |
| --- | --- | --- |
| 로그인·권한 오류 또는 다른 사람의 정보 노출 의심 | 해당 흐름을 중단하고 운영자 확인 전 재시도하지 않음 | 테스트 코드, 시각, 화면 경로만 기록 |
| 코트·비용·일정 정보가 실제와 다름 | 모집자에게 정정 또는 매칭 취소를 요청 | 개인정보 없는 상태와 조치만 기록 |
| 수락 후 취소, 불편함, 신고·차단 요청 | 앱 기능 대신 확정된 운영 문의 채널로 안내 | 운영 채널의 별도 정책에 따라 처리 |
| 결제·환불 요청 | Rally On이 결제·환불을 처리하지 않음을 안내 | 요청 유형만 집계 |

## 9. 종료 후 판단

운영자는 기능 추가 요청을 바로 구현하지 않고 아래 질문으로 결과를 정리한다.

- 참가자는 실력·목적·지역·코트 상태만으로 신청 가능 여부를 판단했는가?
- 상세를 봤지만 신청하지 않은 가장 큰 이유는 무엇인가?
- 모집자는 신청자를 검토하고 수락·거절하는 흐름을 부담 없이 완료했는가?
- 코트 예약·비용 조율 때문에 매칭 등록이나 신청이 반복해서 막혔는가?
- Court Partner Pilot에서 가장 먼저 해결해야 할 예약 단계와 운영 흐름은 무엇인가?

Court Partner Pilot은 Core MVP 다음의 필수 서비스 단계다. M9은 Pilot 시작 여부를 판단하는 대신, 초보자가 어느 예약 단계에서 어려움을 겪는지와 Pilot의 화면·운영 방식을 어떻게 설계할지 관찰한다.

## 10. M9 완료 기준

- 5~10명의 참여자에게 동일한 안내와 범위를 적용했다.
- 모집자·참가자 핵심 흐름을 각각 최소 한 번 이상 관찰했다.
- 퍼널 기록과 짧은 인터뷰를 개인정보 원문 없이 남겼다.
- 운영 문의로 처리한 사례와 막힌 단계를 요약했다.
- 다음 단계에서 먼저 반영할 Core MVP 보완과 Court Partner Pilot의 우선 화면·운영 항목을 근거와 함께 결정했다.
